# 自动续派与窗口生命周期优化回执

状态：`DONE`（产品代码、文档、173 项完整回归、干净安装/升级/回退、全新 Agent 前向测试和本机 `0.16.0` 插件刷新均已通过）。本文不代表任何真实业务项目已被派发。

## Boss 提出的问题

1. 上一项任务已经合法 `DONE` 后，中央不应再等待 Boss 说“继续”，而应直接派发下一批合格任务。
2. 沿用旧窗口还是新开窗口，应由中央依据上下文和风险自行判断。
3. 一个任务窗口不能无限复用：最多只做两项任务，且第 2 项必须等第 1 项完成；做完第 2 项后永久退役。

## 新增

- C03 窗口承接历史：稳定窗口 ID 与当前任务分离，记录第几次承接、任务身份、标题、派发、开始和完成时间。
- C06 不可变 `successorDispatch`：Boss 最终批准 `DONE` 后，明确要求唯一中央自动重算并派发原启动图内的新近合格任务。
- 窗口状态 `AVAILABLE_FOR_REUSE` 与 `RETIRED`。
- C05/C10 两道两任务上限硬门禁，禁止第 3 项进入同一窗口。
- C09 实际消费 C06 续派触发，逐项运行 C05 与 C10 准备；单项阻塞不连带阻断其他合格任务。
- 同一验收触发可按实时总账重入：已有派发单不重复，解除阻塞的任务写下一版不可覆盖批次继续派发。
- 第 2 承接槽由 C05 原子预留；运行时失败时保留现场，并可由 C08 依据 `reservedForTaskId` 进入受控恢复。

## 修改

- 中央 Skill：`DONE` 后不再询问“是否继续”；直接按既有范围批准运行 C05 → C10。
- C05：中央可指定旧窗口；只有完成过一项且空闲的 Terra 窗口可承接第 2 项。
- C10：第 2 项复用同一真实窗口，更新完整任务标题并追加承接记录；确认时再次核对上限。
- C06：`DONE` 时结束当前任务的活动子 Agent，清空窗口当前任务，并根据承接次数变为可复用或退役。
- C08：任务事件按 `currentTaskId` 核对，因此复用后的第 2 项仍能正确回传给当前中央。

## 唯一归口与复用

- 详细任务和窗口状态仍只归 C03，没有建立第二套任务中心。
- C06 + Boss 仍是唯一 `DONE` 路径；自动续派只发生在合法 `DONE` 之后。
- C05 仍归口对象冲突和窗口机械资格，C10 仍归口真实运行派发。
- 原中央启动图的范围化批准继续复用；没有扩大授权。

## 风险与硬停

- 自动续派不会绕过 C04、C05、C10，也不会把任务包或派发单当成真实运行成功。
- 任务、写入对象、唯一写入方、依赖、风险或项目绑定变化时，受影响任务必须重新交 Boss；无关任务不被全局阻断。
- 多个窗口都可复用时由中央判断；无法证明上下文适配时新开更安全。
- 旧版已完成窗口只有状态可证明时才兼容复用；不明状态不能猜。

5. 尝试给该窗口第 3 项，C05/C10 必须拒绝；中央应改为新开窗口。
