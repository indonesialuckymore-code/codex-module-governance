# v0.22 Codex 原生运行优化回执

## 状态

`DONE`（产品程序与隔离测试完成；真实业务项目需在新中央任务中做运行验收）

## Boss 提出的问题

Codex 已提供更完整的任务、工作树、权限、插件和界面管理能力。原系统虽然已能强制 Terra、自动续派和持久回传，但仍有三处可以加强：

1. 任务权限没有进入 C10 运行确认，完整访问仍可能被误当作合格窗口；
2. 中央对多个原生任务的等待、换代和界面整理没有形成统一操作合同；
3. 侧栏标题、分组、置顶、归档等界面状态可能被误认为 C03 的真实任务状态。

## 已完成

### 1. Terra 与权限双门禁

- C10 运行确认协议升级为 `0.17.0`；任务窗口和一级子 Agent 除 Terra 回执外，必须提供 `permissionControl`。
- 任务权限固定为 `WORKTREE_SCOPED`；允许 `:workspace`、`qianyi-task-terra` 和旧运行时兼容的 `workspace-write`。
- `:danger-full-access`、`danger-full-access`、`full-access`、缺证据、证据与运行身份不一致均拒绝，C03 保持原状态。
- 一级子 Agent默认继承父任务权限；继承 profile 和证据引用必须一致。
- C05 只把同时具有 Terra 与受限权限凭据的窗口列为可复用窗口；无权限凭据的旧窗口不能承接第二项。

### 2. 原生任务生命周期合同

- 新建任务：`create_thread`；复用任务：`send_message_to_thread`；创建后统一 `read_thread` 回读。
- 并行监控：`wait_threads`，每批最多 8 个；完成或需要注意时才唤醒中央。
- 第二项任务承接：更新完整任务标题并回读，仍受每窗口两项上限。
- 中央/裁定计划换代：可先 fork 复制已完成对话作为阅读材料，再以 C08 交接包校验和激活；fork 本身不算接管。
- 当前中央/裁定可置顶；任务窗口不置顶。只有 C06 + Boss `DONE` 且窗口 `RETIRED` 才允许归档。

### 3. 单一事实源保持不变

- C03：唯一详细任务、窗口、子 Agent 与对象占用状态；
- C08：角色连续性、交接包、持久事件箱与自动回传入口；
- C14：原生消息送达、确认和指令结果；
- 原生任务标题、项目分组、置顶、归档和界面“完成”状态只作投影，不能反向推进治理状态。

### 4. 既有缺口一并收口

- 保留并验证 `C08_RETURN_VALIDATION_ABORT`：独立验收异常中止时写不可变中止回执，释放的是验收槽预留，不会把业务任务标为完成或释放业务占用。
- Claude Code 协作本轮不施工；只保留既有模块边界，避免在 Claude 模块尚未完成时提前建立双中央通信。

## 不变的核心

- Boss + 唯一总设计师负责全项目施工大纲；Codex 中央不成为全系统第三大脑。
- 中央默认 Sol，任务窗口和一级子 Agent默认 Terra。
- Boss 的启动图批准、C04 任务包、C05 占用、C10 两段式派发、C08/C14 回传、C06 独立验收与 Boss 最终 `DONE` 顺序不变。
- 每个任务窗口最多承接两项串行任务；任务窗口最多三个一级子 Agent；父窗口仍独自对最终质量负责。
- 程序包与仓库外私有工程总账分离；升级不迁移、不覆盖业务数据。

## 剩余运行风险

1. 当前原生建窗接口没有单独的每任务权限 Profile 参数；系统可验收权限证据，但不能把提示词冒充平台级权限切换。
2. 启用新版 Codex 权限 Profile 前需核对本机运行版本；旧 `sandbox_mode` 与新 Profile 不能混用。v0.22 不静默修改用户全局设置。
3. 工作树只隔离 Git 文件，不隔离 Lark、AnyCross、数据库、部署、共享账号或外部入口；C05 的对象占用仍是必需门槛。
4. 本报告证明治理产品程序通过，不代表任何真实业务任务已重新派发或验收。
