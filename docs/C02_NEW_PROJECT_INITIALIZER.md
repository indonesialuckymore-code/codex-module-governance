# C02 新项目初始化器

## 它解决什么问题

当你准备启动一个 Codex 模块项目时，C02 先在你指定的私有目录中查找旧项目、同名项目和近似项目。确认没有冲突后，它只创建一张项目启动卡和一份初始化回执。

这一步的业务作用是防止同一个项目被重复建档、重复开工或误以为已有总账。它不是工程总账，更不承担派工、任务窗口、证据、对象锁或跨模块协调。

## 写入前后分别发生什么

| 阶段 | 系统做什么 | 不会做什么 |
|---|---|---|
| 只读查重 | 读取私有项目索引，检查编号、同名和近似名称 | 不创建任何目录或文件，不派发任务 |
| Boss 批准建档 | 创建项目启动卡、初始化回执和索引条目 | 不创建工程总账、TEST、任务、窗口、子 Agent 或业务对象 |
| 创建后 | 标记为 `PROJECT_REGISTERED`，提示下一关 C03 | 不把项目标记为 `DONE` 或“可施工” |

## 私有目录结构

以下结构只在用户选定的仓库外私有目录中出现，禁止提交到 GitHub：

```text
<private-data-root>/
└── project-registry/
    ├── projects-index.json
    └── project-cards/
        └── <project-id>/
            ├── project-card.json
            └── initialization-receipt.json
```

项目启动卡保存项目名称和不含业务数据的范围摘要。实际任务、真实证据、TEST ID、客户和财务数据都不应放在这里。

## 调用方式

在 Codex 任务中说：

> 启动新项目建档，先检查旧版、半成品和平行机制，先不要派发。

系统会依次确认项目名称、项目编号、范围摘要和私有数据目录，然后先查重。只有你明确说“批准建档”后，才会创建启动卡。

## 查重结果如何理解

- `READY_FOR_BOSS_APPROVAL`：没有查到冲突，等待 Boss 批准创建。
- `REUSE_EXISTING_PROJECT_CARD`：编号已存在，应回到已有项目卡，不能新建第二份。
- `REVIEW_REUSE_OR_MIGRATE`：同名或近似项目存在，需要 Boss 决定复用、迁移评估或另行裁定。
- `REFUSED`：目录、配置或索引不安全/不完整；系统没有创建或覆盖任何数据。

## 验收方法

1. 在仓库外新建一个空的私人目录。
2. 用一个虚构项目名称先执行只读查重，确认目录仍为空。
3. 明确批准建档后，确认只出现上述三个 JSON 文件/对象。
4. 打开 `project-card.json`：`dispatchAllowed`、`testCreationAllowed`、`businessWriteAllowed` 都必须为 `false`。
5. 对同一项目编号再次查重：必须返回复用已有项目卡，而不是创建第二份。
6. 把私有目录放到任意 Git 工作树内再测试：必须被拒绝，且不生成文件。

## 剩余风险

C02 只解决“安全建档”，还没有跨模块工程总账的最终归口。因此项目启动卡建立后，仍必须等待 Boss + Fable 5 对 C03 的总账载体、分区和唯一写入者作出裁定，才可进入任务、窗口和证据管理。
