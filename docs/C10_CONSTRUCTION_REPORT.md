# C10 施工报告

## 状态

`DONE`（产品调度合同和项目归属门禁通过；真实业务仍按各任务包施工）

## 当前能力

- 绿/黄/红调度分类和派发准备→真实运行确认两阶段；
- 单任务批准与中央启动图范围化批准；
- 同一波多个合格任务可批量派发，后续波次仍须前置 `DONE` 和 C05 复核；
- 新建和复用任务窗口、最多 3 个 Terra 一级子 Agent及父窗口统一汇总；
- 派发前绑定 Codex 保存项目，Git 默认标准 worktree；
- 创建后验证项目 ID、运行环境和目录，错误项目或自定义目录不写 C03；
- 平台不能自动建窗时只生成可复制包，不伪造真实运行成功。

## 本轮问题与修复

现场发现任务虽然拿到了项目引用，但被创建到中央自造的 `/Documents/Codex/.../task-id` 目录，Codex 左栏仍显示在“最近”。本轮把项目归属从提示词升级为 C10 机械合同：派发单保存 `runtimeTarget`，运行确认必须回传相同的保存项目 ID 和标准 local/worktree 目录，否则返回 `NEEDS_REVIEW` 且总账不推进。

中央启动图批准必须绑定启动图 ID、SHA-256、波次和获批任务清单；任务不在批准清单中就拒绝，避免把“一次批准”扩大成无限授权。

## 验收

- C10 独立隔离测试覆盖绿黄红、授权、批量范围、项目归属、自定义目录拒绝、运行确认、幂等、失联、子 Agent 和手工降级；
- C09 前向合同检查中央必须一次列全决策和任务，并使用保存项目派发；
- 官方 Skill 结构校验、插件合同和 C01–C13 全回归必须全部通过；
- 实际创建真实项目任务仍须在安装新版后做一次 UI 前向验收：新任务应显示在原项目下，磁盘路径为 Codex 标准 worktree，而不是中央自造目录。

## 剩余风险

- worktree 只隔离本地 Git 文件，不隔离 Lark Base、AnyCross、数据库、部署或共享账号；C05 仍须实时检查外部对象唯一写入。
- 已经创建在“最近”中的旧任务不会被程序静默迁移；完成后可归档，或经 Boss 明确要求另做任务迁移。
