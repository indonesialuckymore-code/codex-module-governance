# C09 中央施工控制器

## Boss 得到什么

现在 Codex 模块有且只有一个中央入口。Boss 可以直接用业务语言说“新建项目”“生成下一任务包”“验收这个回传”“这个阻塞我不能裁定”或“窗口失联了”，中央会先查唯一工程总账，再把请求送到 C02–C08 中唯一正确的能力。

这不是第三套任务中心。详细任务状态仍只保存在 C03；C09 只判断“下一步该由谁处理”。

## 处理顺序

1. 确认请求来自 Boss，并识别项目与意图。
2. 验证能力登记表中只有一个中央入口。
3. 新项目走 C02；已有项目必须先读 C03 的已验证总账。
4. 若项目处于失联冻结，任何普通动作都先转 C08。
5. 正常状态下按意图选择 C03–C08 中一个主能力。
6. 写入意图没有 Boss 明确批准就拒绝；即使批准，也仍须经过下游能力自己的检查。

## 当前明确不能做的事

- 不修改真实业务系统、页面、数据库或自动化。
- 不代替 Boss 做最终裁定。
- 不建立跨模块详细总账。
- 不在 C10 完成前真实创建任务窗口、派一级子 Agent 或恢复业务施工。

## 模型和子 Agent 规则

- 中央：`gpt-5.6-sol`。
- 任务窗口与一级子 Agent：`gpt-5.6-terra`。
- 每个父任务窗口最多 3 个一级子 Agent。
- 禁止子 Agent 再派下级 Agent。

## 验收

运行：

```bash
./scripts/verify-c09.sh
```

合格结果必须同时证明：

- 唯一中央数量为 1；
- C02–C08 均能被正确选择；
- 失联状态优先转 C08；
- 未授权写入被拒绝；
- C10 未完成时派发被硬拦；
- 路由前后工程总账摘要不变；
- C01–C08 原有测试全部无回归。
