# 0.22.1 新项目启动修复回执

## 问题理解

`0.22.0` 的治理主线正确，但新项目首次运行存在五个执行缝隙：

1. 调用“中央工作台”的窗口可能再创建另一个中央，造成首次身份分叉。
2. C03 只校验 `writer-id=codex-module-central`，旧中央或其他窗口可能冒用这个名称继续写账。
3. C04 草案、C05 审查和 C10 派发可以引用不同 Boss 批准，容易重复请示或误用授权。
4. 新 Git 任务先创建 worktree 时可能回读空 `projectId`，再往返修复会产生多个候选窗口。
5. 任务窗口与中央共享过宽可写根时，任务窗口在文件层面也能碰到中央私有总账，会破坏“中央唯一写入”。

## 修复结果

### 1. 首代中央不再分叉

- C08 初始化同时要求 `callingThreadRef` 和 `centralThreadRef`。
- 两者必须是同一当前原生任务；否则拒绝初始化。
- 业务含义：Boss 在哪个新窗口启动中央，那个窗口就是 `CURRENT_CENTRAL G1`，不再多开一个中央。

### 2. 当前中央原生身份门

- C08 路由尚未建立时，保留 C03 启动引导能力。
- C08 路由建立后，所有会变更 C03 的控制器必须回传 `callerThreadRef`，并与路由中唯一活跃 `CURRENT_CENTRAL` 机械对账。
- 旧中央、任务窗口、缺少身份或只冒用 writer 名称的调用均被拒绝。

### 3. 一次批准、三道机械门

- C04 仍只生成不可单独派发的任务合同草案。
- 已批准中央启动图范围内，C05 与 C10 必须使用同一 `bossApprovalRef`；不再对相同范围逐任务重复问 Boss。
- C10 派发单内嵌真正要给任务窗口执行的 `taskPackage`，不再依赖一个并未生成的“最终任务包路径”。

### 4. 新 Git 任务改为 local 引导后进 worktree

- 第一段：在已保存 Codex 项目中以 `project + local` 创建引导任务，先读回正确 `projectId`。
- 第二段：Git 任务通过 `LOCAL_BOOTSTRAP_TO_WORKTREE` 受控交接到同一项目的标准 worktree。
- 任一阶段空项目、目录不匹配或交接失败，都不写 C03；未确认候选交 C08 冻结/退役，不再循环创建平行窗口。

### 5. 任务窗口不再碰中央私有总账

- 合格 profile 只保留 `:workspace` 和 `qianyi-task-terra`，通用 `workspace-write` 不再视为足够精确的任务证据。
- C10 要求结构化 `writableRoots`，当前运行目录必须位于其中。
- `governanceDataRootAccess` 必须为 `DENIED`；任一可写根包含中央私有目录都拒绝进入 `IN_PROGRESS`。
- 一级子 Agent 必须继承同一 profile 和同一可写根边界。

## 影响范围

- 变更了 C03、C05、C06、C07、C08、C09、C10、C11 内部控制器的中央身份传递。
- 变更了新建 Git 任务的项目绑定顺序和 C10 运行确认合同。
- 收紧了任务窗口和一级子 Agent 的权限证据。
- 不修改既有私有工程总账、业务数据、C06 + Boss 的 `DONE` 门，也不增加第二套中央。

## 验收证据

- 修复前基线：195 项测试通过。
- 新增/修订后：202 项 Python 回归全部通过。
- 专项覆盖：首代中央必须是调用窗口、旧中央写账拒绝、C05/C10 批准引用一致、Git local 引导至 worktree、空项目拒绝、私有治理目录不可见、Terra 与窗口两任务上限原回归。

## Boss 发布后验收步骤

1. 新开一个 Sol 任务，从唯一“中央工作台”启动新项目。
2. 确认它直接将当前任务登记为 `CURRENT_CENTRAL G1`，没有再创建第二个中央。
3. 批准一份包含两个无冲突任务的启动图；确认不逐任务重复问批准。
4. 检查每个新 Git 任务的运行回执：先有同项目 local 引导记录，再有标准 worktree 最终任务；左侧项目分组、`projectId`、标题和 Terra 应一致。
5. 检查权限回执：可写根只是当前项目/worktree，中央私有治理目录显示 `DENIED`。
6. 从一个非当前中央窗口尝试更新总账；应得到 `LEDGER_CALLER_NOT_CURRENT_CENTRAL`，总账摘要不变。

## 剩余风险

- 本版修复了治理程序与 Skill，但不会静默修改用户全局 Codex 权限配置。若当前全局可写根仍包含中央私有目录，新任务会正确地被 C10 拦住，而不是冒险开工。
- `callerThreadRef` 是治理层身份证据，不是操作系统级加密令牌。因此任务窗口无法访问中央私有数据目录是必须的第二道隔离。
- 当前是本地修复候选版；未经远端推送、Git 标签、重新安装和真实 Codex UI 前向验收，不得称为已发布稳定版。
