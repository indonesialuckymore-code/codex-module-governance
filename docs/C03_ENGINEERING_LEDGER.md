# C03 Codex 模块工程总账

## 这本账是什么

C03 是 Codex 模块的唯一详细施工账本。它记录 Codex 自己的任务、窗口、一级子 Agent、对象占用、证据引用、裁定引用、Skill 状态和不可覆盖回执。

它不是 Boss + Fable 5 的施工大纲，不记录 Claude 的详细任务，也不是业务系统数据库。

## 三层分工

| 层级 | 维护什么 | 不维护什么 |
|---|---|---|
| Boss + Fable 5 | 全局路线、优先级、模块归属、跨模块交接摘要 | Codex/Claude 的细任务、窗口、对象占用 |
| Codex 模块中央 | Codex 详细总账的唯一写入 | Claude 详细总账、业务施工 |
| 任务窗口及子 Agent | 向父窗口回报施工结果 | 直接改总账、宣布 `DONE` |

## 账本如何防错

1. 只有 `codex-module-central` 能写入。
2. 每次变更都会在私有目录生成不可覆盖回执，回执保存变更后的完整账本快照和校验摘要。
3. 同一个完成信号第二次到达时，只回报“已接收”，不会再次推进任务。
4. 两个不同责任人声明同一对象时，账本保留两份声明，标记 `CONFLICT` 和硬停；它不冒充外部系统的写前锁。
5. `DONE` 被 C03 明确拒绝，必须等待 C06 独立验收和 Boss 批准。
6. C03 的低层 `register-window` 只用于恢复/手工证据登记：不带 Terra 模型证据的窗口会记为 `UNVERIFIED`，不得被 C05/C10 复用。正常派发必须经 C10 的原生模型参数确认。

## 私有目录结构

```text
<private-data-root>/
├── project-registry/                 # C02 项目启动卡
└── module-ledgers/
    └── <project-id>/
        ├── ledger.json               # 当前 Codex 模块账本
        └── receipts/                 # 不可覆盖的历史回执
```

这些文件禁止进入产品 GitHub 仓库。

## 验收方法

1. 先用 C02 建立一个虚构项目启动卡。
2. 运行 C03 的只读初始化预演；应显示“等待 Boss 批准”。
3. 以模块中央身份初始化账本；应只生成账本和初始回执。
4. 用 Fable 或任务窗口身份尝试登记任务；必须被拒绝。
5. 登记任务、接收一次完成信号，再重复发送相同信号；第二次不能改变任务状态。
6. 让两个虚构任务声明同一对象；应保留两份声明并产生硬停。
7. 尝试手改回执后运行账本校验；必须报告回执链不一致。

## 当前边界

C03 已提供记录、状态门禁、完整性校验和 C02→C03 的启动卡迁移。C04–C10 已分别接入任务包、占用、验收、裁定、恢复、中央路由和两段式调度；它们仍不构成外部系统原生写前锁。
