# C12 自然语言调用入口

## 您现在怎么调用

安装并启用本插件后，直接在 Codex 任务里说业务话即可，不需要记 C02–C11、脚本名或参数。Boss 可显式选择或输入 `$central-workbench`；它是唯一可见的中央入口，内部才使用 C12 自然语言解析和 C09 中央控制协议。

OpenAI 官方说明中，Skill 可以由与说明匹配的自然语言自动触发，也可以在 Codex 中通过 Skill 选择器或 `$` 显式调用：[Build skills](https://learn.chatgpt.com/docs/build-skills#how-chatgpt-and-codex-use-skills)。

## 最常用的说法

| 您说 | 系统先做什么 | 会不会直接施工 |
|---|---|---|
| “启动新项目” | 询问项目编号，转 C02 做查重和建档准备 | 不会 |
| “初始化项目总账” | 转 C03 准备唯一详细总账 | 不会绕过批准 |
| “查看当前总账和下一个候选任务” | 转 C03 只读 | 不会 |
| “生成任务包，不要派发” | 转 C04 生成待审草案 | 不会 |
| “检查冲突，判断新开还是沿用窗口” | 转 C05 核对对象占用 | 不会 |
| “批准派发这个任务包” | 转 C10 进入两段式派发 | 不会直接成功；还要下游门禁和真实运行确认 |
| “任务完成了，开始验收” | 先检查 C08 回传票据，再转 C06 独立读回证据 | 无票据不算回传；不会直接 `DONE` |
| “这个问题我不能裁定，请中央后台给意见” | 转 C07 整理顾问请求 | 意见只回您，不回任务窗口 |
| “窗口失联了，先冻结现场” | 转 C08 保留占用并冻结 | 不会自动重派 |
| “撤销任务” | 正常项目转 C03 记录撤销请求；失联冻结项目优先转 C08 | 不会自动释放占用 |
| “固定一个外部 Skill” | 转 C11 审查来源、版本、许可证和权限 | 不会自动安装 |

## 三种调用状态

- **只看**：例如“只看总账，不要执行”。系统只读，不准备写入动作。
- **准备**：例如“生成任务包，不要派发”。系统准备材料，等您审阅。
- **批准执行**：例如“批准派发任务包 package-001”。表示当前对象已获您批准，但仍需通过对应模块的安全门。

“批准”不是万能口令。如果紧邻的上一条提议只有一个明确对象，您可以直接回复“批准”；如果当前对象不唯一，系统必须问您批准哪一项，不能把批准套到旧任务、另一个项目或另一个窗口。

## 系统会自动补什么

- 只有一个项目时，可以自动沿用该项目。
- 只有一个符合条件的任务、任务包、验收、恢复事件或窗口时，可以自动补齐编号。
- 候选不止一个时，只问一个最关键问题，不替您选择。

## 永久边界

- C12 是 `central-workbench` 内部使用的前台翻译协议，C09 仍是唯一中央协议，C03 仍是唯一详细总账。
- C12 不保存原始口语，不另建任务状态，不绕过 C02–C11 的批准和验收门禁，也不作为第二个 `/` 菜单入口。
- 一句话包含多个动作时，系统要求拆开，避免错误排序或扩大授权。
- 请勿在调用内容中粘贴密码、密钥、Cookie、令牌或验证码。
- C12 完成不等于其他人下载后已完成干净安装；安装、升级和回退验收仍属于 C13。

## Boss 验收

1. 新开一个 Codex 任务，直接说“查看当前总账和下一个候选任务”；应进入只读。
2. 说“生成任务包，不要派发”；应只准备草案，不能创建任务窗口。
3. 单独说“批准”；若对象不唯一，应追问具体对象。
4. 说“批准派发任务包，但只看不要执行”；应要求确认只看还是执行。
5. 说“任务完成了，开始验收”；应先要求或读取 `TASK_EVENT_QUEUED` 回传票据，再进入 C06，不能直接显示 `DONE`。
