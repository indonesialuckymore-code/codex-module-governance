# 版本与发布规则

## 版本策略

- `0.22.1` 当前待发布修复候选版：不增加第二套中央或总账；强制首次调用窗口直接成为 `CURRENT_CENTRAL G1`，C08 激活后的所有写账必须绑定当前中央原生任务 ID；强制 C05 与 C10 使用同一 Boss 批准引用；新 Git 任务改为先 `project + local` 建立归属，再交接到同项目标准 worktree；任务窗口必须声明可写根并拒绝访问中央私有治理目录。尚未标记为 Git 稳定版。
- `0.22.0` 当前 Git 私有稳定版：保留唯一“中央工作台”入口与全部治理核心；所有新建或复用的任务窗口、一级子 Agent 必须同时通过 Terra、工作区受限权限、保存项目与真实运行 ID 门禁；加入原生任务批量等待、计划换代 fork/handoff、标题/置顶/归档界面投影；不迁移工程总账、事件箱、任务身份或既有窗口；Git 稳定标签为 `v0.22.0`。
- `0.21.0` 上一 Git 稳定版：保留唯一“中央工作台”入口；所有新建或复用的任务窗口、一级子 Agent 必须由原生运行参数指定 `gpt-5.6-terra`，并以运行凭据通过 C10 确认后才能进入 `IN_PROGRESS`；Git 稳定标签为 `v0.21.0`。
- `0.20.0` 上一 Git 稳定版：Boss 在 `/` 菜单只看见“中央工作台” (`central-workbench`)；C09 中央控制与 C12 自然语言解析改为内部协议，不迁移工程总账、事件箱、任务身份或既有窗口；Git 稳定标签为 `v0.20.0`。
- `0.17.0` 历史施工版：在 `0.16.0` 上加入质量受控的主动子 Agent 协作、原范围运行中补派、结构化回传、父窗口质量闸门和 C06 闸门链。
- `0.18.0` 历史施工版：在 `0.17.0` 上加入自动回传收件箱、持久投递回执、中央摘要隔离、单槽独立验收和范围内自动送验；不改变 C06 + Boss 才能 `DONE` 的合同。
- `0.19.0` 正式私有安装版：在 `0.18.0` 上加入 C14 原生任务消息桥，区分“私有票据已入箱、平台已发送、收件任务已确认、指令已处理”，并让未确认消息在中央换代后重路由。

- 使用语义化版本：`MAJOR.MINOR.PATCH`。
- `0.1.0` 仅代表 C01 产品骨架，不代表可用于业务施工。
- `0.2.0` 加入 C02 私有新项目建档；不代表工程总账、派工或业务施工已具备。
- `0.3.0` 加入 C03 Codex 模块详细总账和不可覆盖回执；不代表任务派发、独立验收或业务施工已具备。
- `0.4.0` 加入 C04 待审施工任务包；不代表任务已派发、对象占用已通过、独立验收或业务施工已具备。
- `0.5.0` 加入 C05 原子占用预留、冲突硬停和新旧窗口建议；不代表任务已派发或具备外部系统原生写前锁。
- `0.6.0` 加入 C06 独立回传验收及 Boss 最终 `DONE` 门槛；不代表已验收任何真实业务链路。
- `0.7.0` 加入 C07 裁定请求、只回 Boss 的顾问意见及原窗口决定回传；不代表顾问可替 Boss 裁定或自动执行。
- `0.8.0` 加入 C08 失联冻结、总账续读、恢复决定及完成/取消后的受控占用释放；不代表业务施工会自动恢复。
- `0.9.0` 把既有中央施工控制器接入 C02–C08，并机械验证唯一入口、模型政策和 C10 能力缺口；不代表已经能真实派发窗口或子 Agent。
- `0.10.0` 加入绿黄红派发、任务窗口新建/复用、最多 3 个一级子 Agent、真实运行确认和父窗口汇总；不代表 C12 自然语言入口或 C13 干净安装已经完成。
- `0.11.0` 加入外部 Skill 私有登记、版本与许可证门禁、替代关系和安全降级；不代表外部 Skill 已被自动安装或调用。
- `0.12.0` 加入 Boss 自然语言调用入口、唯一候选补齐和含糊批准保护；不代表 C13 干净安装、升级和回退已通过。
- `0.13.0` 完成私有 GitHub Marketplace 安装、隔离升级、失败保全、回退和手工建窗降级验收；不代表任何业务链已上线或具备外部原生写前锁。
- `0.14.0` 为未打标签的中央启动图、批量批准、依赖波次和保存项目绑定施工版。
- `0.15.0` 加入任务 ID 全链一致、中央/裁定换代不断线和持久任务事件箱；不代表真实业务任务已迁移或验收。
- `0.16.0` 加入 `DONE` 后自动续派、中央自主新开/复用判断、窗口两任务串行上限和第二项完成后退役；不代表任何真实业务项目已自动派发。
- `0.17.0` 加入任务窗口三检查点主动委派、0–3 个弹性一级 Agent、无共享写入风险的运行中补派、结构化回传和父窗口质量闸门；不改变 C06 + Boss 才能 `DONE` 的合同。
- `0.18.0` 加入 C08 回传票据和收件箱：任务窗口必须取得 `TASK_EVENT_QUEUED` 回执，中央只收摘要并一次只预留一个独立验收窗口；Boss 可批准范围内自动送验政策，但通过后仍须最终批准才记录 `DONE`。
- `0.19.0` 加入 C14 双向通信：C08 回传票据仍是事实源，但任务窗口必须使用 Codex 原生消息通知当前中央，并以收件确认避免“假回传”；中央到任务窗口的指令也有送达、确认和结果回执。C14 不改变 C03 的唯一详细任务状态，也不改变 C06 + Boss 的 `DONE` 合同。
- `0.20.0` 将两个可见中央入口收敛为 `central-workbench`；C09/C12 的内部协议身份和私有数据合同不变，因此不引入第二中央或总账迁移。
- `0.21.0` 将 C10 派发、运行确认、子 Agent 回传和父窗口质量闸门协议升级为 `0.16.0`，增加 Terra 原生模型参数与回执关联门；不满足者不能被写入为运行中任务。
- `0.22.0` 将 C10 协议升级为 `0.17.0`，增加 `WORKTREE_SCOPED` 权限回执、完整访问拒绝、原生任务动作合同和界面投影边界；C03/C08/C14 的事实源职责不变。
- `0.22.1` 收紧新项目首次运行和任务隔离协议；已在运行的 `0.22.0` 任务可受控完成，但旧待确认派发单和缺少可写根/私有目录拒绝证据的旧窗口不得继续确认或承接第二项任务。
- 影响配置 schema 时，必须提供迁移说明、兼容范围和回退方法。

## 0.11.0 → 0.12.0 配置迁移

- 把私有配置的 `schemaVersion` 更新为 `0.12.0`，并按 `config/module-config.example.json` 增加 `naturalLanguageGateway` 区块。
- C03 私有工程总账及既有 C02–C11 产物不迁移、不覆盖；C12 不建立自己的持久状态。
- 旧的 C09 `0.11.0` 路由请求不继续复用，应由 C12 重新生成 `0.12.0` 标准请求。
- 若需回退程序到 `0.11.0`，先恢复上一版私有配置；用户总账、证据和外部 Skill 登记不删除。

## 0.12.0 → 0.13.0 配置迁移

- 无用户数据或工程总账迁移；治理协议和私有配置 schema 继续使用 `0.12.0`。
- 只升级插件程序包和 Marketplace 名称；旧的程序备份可恢复，用户私有目录保持不变。

## 0.13.0 → 当前未发布施工版配置迁移

- 私有配置 `schemaVersion` 更新为 `0.14.0`，在 `dispatch` 增加范围化批量批准、依赖完成后波次放行、保存项目强绑定和单批最多 8 个监控任务。
- C10 派发请求、运行确认和子 Agent 回传协议更新为 `0.14.0`；旧 `0.10.0` 派发单不会静默复用，应由中央按最新启动图重新生成。
- C03 工程总账、既有任务状态、证据和占用不迁移、不覆盖；新增的本机项目路径只保存在私有 C10 派发/确认产物中。
- 回退到 `v0.13.0` 时恢复旧私有配置副本；不删除当前工程总账或业务证据。

## 0.14.0 → 0.15.0 运行材料迁移

- 配置 schema 仍为 `0.14.0`；新增的角色路由、交接包和事件箱在仓库外私有目录按需初始化。
- 既有 C03 任务和窗口不批量覆盖；读取时可兼容旧标题，下一次重新生成任务包或新开窗口时写入 `任务ID｜业务名称｜G代际`。
- 旧 C04 任务包缺少 `taskIdentity` 时不得继续派发，应从原 C03 任务重新生成；旧 C10 待确认派发单也应重做。
- 回退到 `v0.13.0` 不删除角色路由、事件箱或工程总账；旧程序只会忽略其不认识的私有材料。

## 0.15.0 → 0.16.0 窗口运行材料迁移

- 新建窗口直接写入 `currentTaskId`、`assignmentCount=1`、`maxAssignments=2` 和 `assignmentHistory`。
- 旧窗口继续可读：首次经新版 C06 完成或 C10 复用时会在不可变总账变更中补齐承接历史，不批量覆盖既有总账。

## 0.16.0 → 0.17.0 子 Agent 质量合同迁移

- C10 请求、运行确认和子 Agent 回传协议升级为 `0.15.0`；旧的待确认 C10 派发单不静默升级，应在原中央启动图范围内重新生成。
- C06 任务窗口回传协议升级为 `0.7.0`，新增 `parentQualityReviewRefs`。未使用子 Agent 的任务填空数组；使用过子 Agent 的任务必须引用 C10 已记录的父窗口质量闸门。
- 私有 C03 总账、既有窗口、既有证据和业务材料不批量迁移、不覆盖。已在运行的旧任务应由 Boss/C08 决定继续按旧协议完成或受控重开，不得混合协议。
- 旧窗口只有其关联任务已合法 `DONE` 且能证明没有当前任务时，才可作为第 2 次承接；不明状态保持不可复用。
- 新版 C06 最终裁定增加 `windowMutation` 和 `successorDispatch`。旧的已完成裁定不会倒推自动派发，中央从当前总账和启动图重新计算。

## 0.17.0 → 0.18.0 自动回传票据迁移

- C06 任务窗口回传协议升级为 `0.8.0`，新增 `returnTicketId` 和 `routeRevisionSeen`。旧 `0.7.0` 回传包不会静默接受；它只能保留为历史证据，不能被聊天文字补成新协议回传。
- 每个新回传先由 C08 写入私有 `return-inbox`，再生成 `TASK_EVENT_QUEUED` 投递回执。只有票据、事件和摘要哈希一致时，中央才可登记完成信号。
- Boss 可在中央启动图范围内配置一次 `AUTO_QUEUE_AND_VALIDATE_WITHIN_APPROVED_SCOPE`。该政策只代替逐票“是否送验收”的重复确认，固定最大并发验收为 1，绝不代替范围变更、例外处理或最终 `DONE` 批准。
- 正在运行的 0.17 任务不得把旧回传包改写覆盖。由 Boss 选择继续按旧版本受控结束，或在同一已批准范围内生成新 `0.8.0` 回传包和新票据；不得混用两代回传材料。
- 回退旧程序不会删除新增字段，但旧程序不理解两任务生命周期，回退期间禁止复用窗口承接第 2 项。

## 0.18.0 → 0.19.0 双向通信迁移

- C08 的 `TASK_EVENT_QUEUED` 继续代表持久票据已进入逻辑中央收件箱；它不再单独代表当前中央聊天已被唤醒。
- 新任务窗口应在 C08 `submit-return` 后按 C14 取得 `DELIVERED` 和 `MESSAGE_ACKNOWLEDGED`。旧回传票据不重写，中央可照旧读取并用 C14 生成新的通知信封。
- C14 通信材料全部留在私有数据目录；程序回退不删除信封、送达、确认或结果回执。旧程序会忽略它们，但不得因此用聊天文字补充成“已收到”。

## 0.19.0 → 0.20.0 入口收敛迁移

- 不迁移私有配置、C03 工程总账、C08 事件箱、任务身份、窗口或证据；升级只替换插件程序。
- 升级后必须新开 Codex 任务，使用唯一的“中央工作台”或 `$central-workbench`；旧“中央处理器”与旧 C12 入口不再作为菜单 Skill 使用。
- 若新任务仍显示两个同名入口，停止选择其中任意一个，先检查 Codex 是否同时加载了旧缓存和新 Marketplace；这属于安装来源重复，不可用第二套总账解决。

## 0.20.0 → 0.21.0 Terra 派发材料迁移

- 新 C10 请求、运行确认、子 Agent 回传、运行中补派和父窗口质量闸门使用 `0.16.0` 协议；旧 `0.15.0` 待确认派发单不静默升级，应在原 Boss 批准范围内重新生成。
- 新窗口确认必须保存 `model=gpt-5.6-terra`、`runtimeModel=gpt-5.6-terra` 和 `modelEnforcement`。旧窗口、C03 手工直登窗口或历史总账不批量改写；缺少模型凭据的窗口只可读取，不得作为第二项任务复用。
- 自动创建以原生建窗调用的 `model` 参数为证据；复用以原生续接调用的 `model` 参数为证据；手工降级仅接受 `export-fallback` 生成包后留存的 Terra 选择证据。
- 回退程序不会删除任何 C03 总账、回执或派发产物。回退后不得继续确认新 `0.16.0` C10 派发单，也不得把缺少模型凭据的窗口重新标记为 Terra。

## 0.21.0 → 0.22.0 原生任务与权限迁移

- 私有配置 schema 更新为 `0.22.0`，新增 `runtimePermissions` 与 `nativeRuntime`；`storage.userDataRoot` 和既有私有数据目录不变。
- 新 C10 请求、运行确认、子 Agent 回传、运行中补派和父窗口质量闸门使用 `0.17.0` 协议；旧 `0.16.0` 待确认派发单不静默升级，应在原 Boss 启动图批准范围内重新生成。
- 新窗口确认必须同时保存 `modelEnforcement` 与 `permissionEnforcement`。旧窗口不批量改写：可继续完成当前任务，但没有受限权限证据时不得承接第二项任务。
- `:danger-full-access`、`danger-full-access` 和 `full-access` 不能作为任务窗口权限。允许 `:workspace`、`qianyi-task-terra` 与旧运行时兼容的 `workspace-write`，且必须保存与运行身份关联的证据。
- 原生 fork/handoff、标题、置顶、归档和任务状态只作 Codex 界面操作；C03 工程总账、C08 交接/事件箱和 C14 通信回执继续是事实源，不从界面倒推状态。
- 本升级不会自动修改用户全局 Codex 配置。升级插件后新开任务；若要启用新版权限 Profile，先按当前 Codex 官方版本要求升级运行时并备份旧配置。
- 回退到 `v0.21.0` 不删除新增权限字段或原生运行材料；旧程序会忽略不认识的字段，但不得继续确认 `0.17.0` 派发单。

## 0.22.0 → 0.22.1 新项目启动修复迁移

- 私有配置 `schemaVersion` 更新为 `0.22.1`。`allowedTaskProfiles` 只保留 `:workspace` 和 `qianyi-task-terra`，并增加 `requireDeclaredWritableRoots=true` 与 `denyGovernanceDataRootAccess=true`。
- 首次中央初始化需同时提供 `callingThreadRef` 和 `centralThreadRef`，两者必须是同一当前任务。C08 角色路由存在后，所有 C03 相关变更都要带当前 `callerThreadRef`；旧中央自动被拒绝。
- 新 Git 任务不再直接建 worktree 候选再做项目绑定补救。C10 先创建 `project + local` 引导任务，读回项目 ID 后只允许一次受控交接到同项目标准 worktree。
- 旧 C10 待确认派发单缺少 `writableRoots` 或 `governanceDataRootAccess=DENIED` 时不得静默升级；按原启动图范围重新生成。已运行窗口可完成当前任务，但缺少证据时不可复用。
- 若用户全局 Codex 可写根包含中央私有治理数据目录，新任务窗口将保持 `PENDING_RUNTIME_CONFIRMATION`。先备份配置，将任务权限收紧为唯一项目根，再用新任务重试；不要删除私有总账。
- 回退到 `v0.22.0` 不删除现有总账、角色路由或回执。回退期间不得确认 `0.22.1` 派发材料。

## 发布策略

- 当前仓库为私有，`allowRemotePublish=false`。
- 没有 Boss 明确批准，不创建公开 Release、不发布 marketplace、不推送用户数据。
- C13 验收通过后，只能宣称“已获私有仓库权限的用户可按文档安装并新开任务使用”；不能宣称未授权公众可访问。
- 发布前必须通过 `./scripts/verify-c13.sh`、官方插件/Skill 校验、远端私有仓库重新克隆和 Codex CLI Marketplace 安装读回。
- 当前可安装基线固定为 Git tag `v0.22.0`；用户安装稳定版不跟随 `main` 漂移。

## 回退策略

- 产品程序升级不得覆盖用户总账或证据。
- 升级前保存用户配置与 schema 版本；失败时恢复到上一兼容程序版本。
- Marketplace 升级应固定可回退的 tag、commit 或上一插件备份；不以删除用户数据作为回退方式。
