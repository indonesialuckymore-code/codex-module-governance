# 版本与发布规则

## 版本策略

- `0.15.0` 本地施工版：在未发布的 0.14 调度合同上加入稳定任务身份、中央/裁定逻辑角色、计划换代、持久任务事件箱和精简裁定影响摘要；Git 稳定标签仍为 `v0.13.0`。

- 使用语义化版本：`MAJOR.MINOR.PATCH`。
- `0.1.0` 仅代表 C01 产品骨架，不代表可用于业务施工。
- `0.2.0` 加入 C02 私有新项目建档；不代表工程总账、派工或业务施工已具备。
- `0.3.0` 加入 C03 Codex 模块详细总账和不可覆盖回执；不代表任务派发、独立验收或业务施工已具备。
- `0.4.0` 加入 C04 待审施工任务包；不代表任务已派发、对象占用已通过、独立验收或业务施工已具备。
- `0.5.0` 加入 C05 原子占用预留、冲突硬停和新旧窗口建议；不代表任务已派发或具备外部系统原生写前锁。
- `0.6.0` 加入 C06 独立回传验收及 Boss 最终 `DONE` 门槛；不代表已验收任何真实业务链路。
- `0.7.0` 加入 C07 裁定请求、只回 Boss 的顾问意见及原窗口决定回传；不代表顾问可替 Boss 裁定或自动执行。
- `0.8.0` 加入 C08 失联冻结、总账续读、恢复决定及完成/取消后的受控占用释放；不代表业务施工会自动恢复。
- `0.9.0` 把既有中央施工控制器接入 C02–C08，并机械验证唯一入口、模型政策和 C10 能力缺口；不代表已经能真实派发窗口或子 Agent。
- `0.10.0` 加入绿黄红派发、任务窗口新建/复用、最多 3 个一级子 Agent、真实运行确认和父窗口汇总；不代表 C12 自然语言入口或 C13 干净安装已经完成。
- `0.11.0` 加入外部 Skill 私有登记、版本与许可证门禁、替代关系和安全降级；不代表外部 Skill 已被自动安装或调用。
- `0.12.0` 加入 Boss 自然语言调用入口、唯一候选补齐和含糊批准保护；不代表 C13 干净安装、升级和回退已通过。
- `0.13.0` 完成私有 GitHub Marketplace 安装、隔离升级、失败保全、回退和手工建窗降级验收；不代表任何业务链已上线或具备外部原生写前锁。
- `0.14.0` 为未打标签的中央启动图、批量批准、依赖波次和保存项目绑定施工版。
- `0.15.0` 加入任务 ID 全链一致、中央/裁定换代不断线和持久任务事件箱；不代表真实业务任务已迁移或验收。
- 影响配置 schema 时，必须提供迁移说明、兼容范围和回退方法。

## 0.11.0 → 0.12.0 配置迁移

- 把私有配置的 `schemaVersion` 更新为 `0.12.0`，并按 `config/module-config.example.json` 增加 `naturalLanguageGateway` 区块。
- C03 私有工程总账及既有 C02–C11 产物不迁移、不覆盖；C12 不建立自己的持久状态。
- 旧的 C09 `0.11.0` 路由请求不继续复用，应由 C12 重新生成 `0.12.0` 标准请求。
- 若需回退程序到 `0.11.0`，先恢复上一版私有配置；用户总账、证据和外部 Skill 登记不删除。

## 0.12.0 → 0.13.0 配置迁移

- 无用户数据或工程总账迁移；治理协议和私有配置 schema 继续使用 `0.12.0`。
- 只升级插件程序包和 Marketplace 名称；旧的程序备份可恢复，用户私有目录保持不变。

## 0.13.0 → 当前未发布施工版配置迁移

- 私有配置 `schemaVersion` 更新为 `0.14.0`，在 `dispatch` 增加范围化批量批准、依赖完成后波次放行、保存项目强绑定和单批最多 8 个监控任务。
- C10 派发请求、运行确认和子 Agent 回传协议更新为 `0.14.0`；旧 `0.10.0` 派发单不会静默复用，应由中央按最新启动图重新生成。
- C03 工程总账、既有任务状态、证据和占用不迁移、不覆盖；新增的本机项目路径只保存在私有 C10 派发/确认产物中。
- 回退到 `v0.13.0` 时恢复旧私有配置副本；不删除当前工程总账或业务证据。

## 0.14.0 → 0.15.0 运行材料迁移

- 配置 schema 仍为 `0.14.0`；新增的角色路由、交接包和事件箱在仓库外私有目录按需初始化。
- 既有 C03 任务和窗口不批量覆盖；读取时可兼容旧标题，下一次重新生成任务包或新开窗口时写入 `任务ID｜业务名称｜G代际`。
- 旧 C04 任务包缺少 `taskIdentity` 时不得继续派发，应从原 C03 任务重新生成；旧 C10 待确认派发单也应重做。
- 回退到 `v0.13.0` 不删除角色路由、事件箱或工程总账；旧程序只会忽略其不认识的私有材料。

## 发布策略

- 当前仓库为私有，`allowRemotePublish=false`。
- 没有 Boss 明确批准，不创建公开 Release、不发布 marketplace、不推送用户数据。
- C13 验收通过后，只能宣称“已获私有仓库权限的用户可按文档安装并新开任务使用”；不能宣称未授权公众可访问。
- 发布前必须通过 `./scripts/verify-c13.sh`、官方插件/Skill 校验、远端私有仓库重新克隆和 Codex CLI Marketplace 安装读回。
- 第一版可安装基线固定为 Git tag `v0.13.0`；用户安装稳定版不跟随 `main` 漂移。

## 回退策略

- 产品程序升级不得覆盖用户总账或证据。
- 升级前保存用户配置与 schema 版本；失败时恢复到上一兼容程序版本。
- Marketplace 升级应固定可回退的 tag、commit 或上一插件备份；不以删除用户数据作为回退方式。
