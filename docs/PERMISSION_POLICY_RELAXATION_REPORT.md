# 0.22.1 权限策略放宽回执

> 历史记录：以下状态、数字和下一步仅对应当时验证，不是当前待办。最新能力与验证边界见[候选版状态](../plugins/codex-module-governance/references/release-status.md)，不要重新执行已退役安装器或恢复强制 Terra。

## Boss 决定

任务窗口和一级子 Agent 不再强制使用自定义工作区受限权限。默认恢复 Codex 原生完全访问；Boss 如需高隔离，只主动选择 Codex 原生 `WORKTREE_SCOPED/:workspace`。系统不再创建、安装或依赖自定义权限 Profile。

系统权限只回答“技术上能做什么”，不能替代业务授权。无论使用哪种权限，任务仍受冻结大纲、中央启动图、C04 任务包、C05 对象占用和 C06 独立验收约束。删除、批量覆盖、付款、正式上线、外发和重大权限变化仍需单独批准。

## 产品合同变化

1. C10 默认派发合同改为 `FULL_ACCESS/full-access`，不再拒绝 `danger-full-access` 或 `full-access`。
2. C10 仍要求真实权限读回并与运行身份绑定；缺证据或 class/profile 不匹配仍拒绝进入 `IN_PROGRESS`。
3. 完全访问回执使用空 `writableRoots` 和 `governanceDataRootAccess=NOT_RESTRICTED`，不伪装成文件层隔离。
4. 受限模式继续要求精确绝对写根、当前运行目录位于写根内，并证明中央私有治理目录为 `DENIED`。
5. C05 允许权限证据完整的完全访问窗口进入复用候选；一级子 Agent 继承父窗口实际权限。
6. 手工建窗降级包默认提示保留完全访问，同时允许 Boss 主动选择受限模式。
7. `qianyi-task-terra` 从产品合同、安装迁移和可选 Profile 中移除；旧配置迁移只负责清理它，不会重新创建。

## 影响范围

- C03：记录两种权限模式及真实证据。
- C05：窗口复用资格接受两种模式。
- C10：准备、确认、补派和手工降级合同接受两种模式。
- 配置与 schema：默认完全访问，受限模式可选。
- 中央工作台与派发 Skill：不再要求 Boss 关闭完全访问。
- 安装、版本、ADR 和运行说明：明确系统权限与业务授权分离。
