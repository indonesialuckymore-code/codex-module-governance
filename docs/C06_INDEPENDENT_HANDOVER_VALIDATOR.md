# C06 回传与独立验收器

## 它解决什么问题

C06 防止施工窗口把“我做完了”直接变成“系统验收完成”。它把流程拆成四层：施工窗口封存材料、C08 回传收件箱取得投递回执、隔离验收窗口独立读回、Boss 最终决定。

```text
任务窗口封存回传包 → C08 returnTicket + TASK_EVENT_QUEUED
       ↓ 中央只读摘要、登记 C03 NEEDS_REVIEW
单槽隔离 C06 逐项独立读回
       ├─ 缺证据 → NEEDS_REVIEW
       ├─ 有失败/阻断风险 → PARTIAL
       ├─ 越界/未知写入/重复数据 → CONFLICT + 硬停
       └─ 全部通过 → PASS_PENDING_BOSS_APPROVAL
                              ↓ Boss 最终批准
                            C03 DONE
                              ↓
              生成续派触发，中央自动重算下一批合格任务
```

## 十类强制证据

改前快照、改后快照、正例、反例、幂等、回滚、日志与记录历史、上游读回、下游读回、TEST 与业务对象编号。每一项都必须由中央独立读回，不能直接相信窗口声明；仍有未确认事项时不得进入最终批准门槛。

## Boss 门槛

1. **送验收政策或单项授权**：Boss 可以逐项允许回传，也可以在中央启动图范围内一次批准自动送验政策。政策只允许票据自动排队和独立验收，范围或风险变化仍交 Boss。
2. **最终完成**：隔离验收全部通过后仍保持 `NEEDS_REVIEW`；Boss 最终批准才写入 `DONE`。

聊天文字、屏幕截图中的“已回传”或普通 C08 事件都不成立。C06 必须能核对 `returnTicketId`、事件 ID、回传摘要哈希和 `TASK_EVENT_QUEUED` 投递回执；缺任一项时拒绝验收。

## 使用过子 Agent 时多一道质量闸门

子 Agent 是为了节省父窗口的处理时间，不是为了降低验收要求。因此只要本次任务使用过一级子 Agent，任务窗口在申请 C06 前还必须提交 C10 父窗口质量闸门：子 Agent 的结构化回传必须齐全；父窗口必须亲自读回关键证据、覆盖正例/反例/幂等/回滚/日志/读回六类验收，并写明每个 Agent 的冲突处理结果。

C06 会校验这个闸门与本次窗口、任务、Agent 回传是否一一对应。缺失、未齐、范围越界、发现未知写入或只拼接原文时，C06 拒绝进入独立验收。这个闸门不替代 C06，也不能宣布 `DONE`。

## 永久边界

- C06 不创建测试数据、不修改真实业务对象、不启停生产入口。
- C06 不释放 C05 对象占用；C08 仅在校验 C06 最终批准及新的 Boss 释放授权后处理安全释放。
- C06 决定同时绑定 C04 包、C05 决定、任务回传、中央复核和实际 C03 写入回执。
- 普通 C03 状态变更仍不能写 `DONE`；只有 C06 最终批准路径可以。
- 验收中出现需要业务裁定的阻塞时，可交 C07 整理顾问请求；C07 不改变 C06 的证据门槛。

## `DONE` 后发生什么

Boss 最终批准时，C06 在同一条总账变更中完成三件事：任务写入 `DONE`；该窗口的当前承接记录写入完成；活动子 Agent 结束。窗口只做过一项时变为 `AVAILABLE_FOR_REUSE`，已经做完第二项时变为 `RETIRED`。

最终裁定还保存 `successorDispatch.required=true`。这不是新增授权，而是提醒唯一中央继续执行已批准的中央启动图：立即重算依赖和占用，符合条件的任务直接进入 C05/C10。若范围、对象、风险、依赖或项目绑定变化，变化部分仍须 Boss 重新决定。
