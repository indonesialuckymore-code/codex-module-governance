# C05 占用与冲突检查器

## 它解决什么问题

C05 在任务真正派发前回答三个问题：是否有人正在写同一对象、两个任务能否并行、应该开新窗口还是沿用旧窗口。它复用 C03 的唯一占用分区，不建立第二套锁。

## 业务流程

```text
C04 待审任务包
  ↓ Boss 审阅任务包与对象范围，并给出依赖/跨模块结论
C05 只读预演
  ├─ 条件不足 → WAITING，不写总账
  ├─ 对象冲突 → CONFLICT_HARD_STOP
  │                候选任务 BLOCKED，不做部分占用
  └─ 无冲突 → 显式应用后整包预留
                   候选任务 READY，仍未实际派发
```

## 冲突规则

- 相同对象：同一个 `objectKey`。
- 父子对象：用同一个 `conflictKey` 表示，例如字段和所属表。
- 任一方为写入，或者任一方为排他资源，则重叠即冲突。
- 两方均为非排他只读时允许并行。
- 外部入口、生产开关、唯一事实源、运行账号等应标记为排他资源。
- 跨模块交集由 Fable 只传交接引用和结论，不复制 Claude 详细总账。

## 窗口判断

- 没有匹配旧窗口：建议新开，默认模型 `gpt-5.6-terra`。
- 只有一个同任务的活动窗口：建议沿用。
- 要求沿用但找不到窗口：等待。
- 同任务出现多个候选窗口：冲突硬停，避免双施工中心。

## 写入边界

- 预演永远不写总账。
- 正式应用仅允许 `codex-module-central`。
- 无冲突时，一次性写入全部对象占用并把任务从 `PLANNED` 推进到 `READY`。
- 有冲突时，不写入候选占用，只把后启动任务设为 `BLOCKED` 并登记硬停。
- 重复应用同一个 review 不重复推进总账。
- C05 不创建窗口、子 Agent、TEST，不执行派发或业务写入。
- C05 决定同时绑定 C04 包、C05 请求、C03 改前快照和实际 C03 写入回执；任一凭证被篡改都不能通过校验。

## 当前边界

C05 是治理层占用，不是操作系统、Git、Base、workflow 或外部服务的原生锁。C08 负责受控释放，C09–C10 已接入中央路由和两段式 Codex 任务调度。
