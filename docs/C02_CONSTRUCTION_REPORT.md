# C02 施工回执：新项目初始化器

## 结果

状态：`NEEDS_REVIEW`。C02 已形成可安装插件中的 `new-project-initializer` 能力和本地校验脚本，但仍等待 Boss 验收；它不代表 C03 或业务施工已放行。

## 本次新增

- 新项目初始化 Skill：先核对项目名称、项目编号、范围摘要和私有数据目录。
- 私有初始化器：先只读查重，再在 Boss 明确批准后创建项目启动卡、初始化回执和项目索引。
- 启动卡及项目索引 schema。
- 重复项目、Git 工作树目录、损坏索引和并发初始化锁的拒绝机制。
- 7 个隔离回归测试、C02 自检脚本和中文使用说明。

## 已验证

| 场景 | 结果 |
|---|---|
| 只读查重 | 通过；不创建目录或文件。 |
| 批准建档 | 通过；只生成启动卡、回执和索引。 |
| 相同编号再次建档 | 通过；返回复用已有项目卡，不覆盖。 |
| 近似名称 | 通过；要求复用/迁移评估或人工裁定。 |
| 私有目录位于 Git 工作树 | 通过；拒绝且不写入。 |
| C01/C02 结构和 JSON | 通过。 |

## 业务影响

这项能力把“我要开一个项目”变成可查重、可回看的私有启动卡，降低重复建项目的风险。它不改现有业务系统、财务数据、工作流、权限、任务窗口或 GitHub 以外的任何对象。

## 未完成与风险

- 跨模块工程总账的载体、分区和唯一写入方仍是 `UNKNOWN`；C02 不能、也没有代替 C03。
- 当前操作系统的官方插件校验器缺少 YAML 依赖，因此本次用其公开字段规则做了无依赖预检；C13 应在干净安装环境完成官方插件安装验收。
- C02 的私有目录中会保存用户填写的项目名称与范围摘要，Boss 必须避免输入客户、账务、账号、密钥或真实施工证据。
