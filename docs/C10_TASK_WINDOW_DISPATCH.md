# C10 任务窗口与一级子 Agent 调度

## Boss 得到什么

批准任务后，中央现在能把 C05 的新开/复用建议转成真实 Codex 调度：新开任务、发送给旧任务，或为父任务创建最多 3 个一级子 Agent。默认都使用 Terra。

## 绿黄红

- 绿：共享只读，不争用写入对象，可以并行。
- 黄：包含写入，但 C05 已完成隔离占用，可以在任务包范围内派发。
- 红：重叠写入、依赖不满足、跨模块不明、总账硬停或失联冻结，拒绝派发。

## 为什么是两段式

派发单只表示“允许尝试”。只有 Codex 运行时返回真实任务和 Agent ID，中央才登记总账并把任务推进为 `IN_PROGRESS`。如果只创建了一部分，不能留下“任务已经派发”的假记录。

## 任务名称不会再对不上

- C03 总账和 C04 任务包统一显示 `任务ID｜业务名称`。
- Codex 任务窗口统一显示 `任务ID｜业务名称｜G1`；重开同一任务依次为 `G2`、`G3`。
- C10 第二阶段同时回读任务 ID、完整标题和代际。任一不符就报告 `TASK_IDENTITY_MISMATCH / NEEDS_REVIEW`，不写总账、不推进任务。
- 任务窗口回传先写 C08 持久事件箱，收件人是 `CURRENT_CENTRAL`；中央换代不影响已有任务窗口。

## 一个窗口最多做两项

- 第 1 项任务完成前，窗口不能接收别的任务。
- 第 1 项经 C06 独立验收并由 Boss 最终批准为 `DONE` 后，窗口进入 `AVAILABLE_FOR_REUSE`；中央可以选择给它唯一一次第 2 项任务，也可以判断新开更安全。
- 第 2 项使用同一个真实窗口 ID，但必须更新为新任务的完整标题，并在总账追加第 2 条承接记录。
- C05 选择第 2 项时先原子预留该窗口唯一剩余名额；若运行时暂时失败，预留不会被静默释放或被其他任务抢走。中央可重试同一派发单；决定放弃时必须以该 `reservedForTaskId` 进入 C08 受控恢复/取消，不能手改总账。
- 第 2 项 `DONE` 后窗口自动进入 `RETIRED`。C05 和 C10 都会拒绝第 3 项，中央只能新开或选择其他只完成过一项的窗口。
- 这项上限是硬规则，不靠中央记忆；因此中央或任务窗口压缩上下文也不会忘记已经做过几项。

## Git 任务如何稳定归入项目

中央先按保存项目 ID 创建标准 worktree，然后同时回读项目 ID 和目录。现场实测表明，个别新初始化项目会出现“worktree 目录正确但项目 ID 为空”的状态，此时任务仍可能显示在“最近”。C10 不重建任务，而是把同一任务原生交接到保存项目根目录完成绑定，再交接回原 worktree。只有最终项目 ID 和 worktree 路径同时正确，才登记 `IN_PROGRESS`。

## 子 Agent 回传

子 Agent 只能把事实、证据和阻塞交给父窗口，不能直接向中央宣布整项完成。所有子 Agent 齐全后，父窗口才可统一回传；随后仍走 C06 和 Boss 最终验收。

## 平台不能自动建窗时

中央对已批准派发单运行 `export-fallback`，生成一个可复制的私有任务包。这个降级包不会把任务推进为 `IN_PROGRESS`，不会登记虚假的窗口 ID，也不会改变对象占用；Boss 把内容复制到手工新建的 Codex 任务后，仍须用真实任务 ID 完成 C10 第二阶段确认。

## 验收

运行 `./scripts/verify-c10.sh`。除原有绿黄红、项目归属和真实运行确认外，必须证明第 1 项完成后可复用、第二承接槽不能被并发抢占、第 2 项沿用同一窗口、第 2 项完成后退役、第 3 项被拒绝。
