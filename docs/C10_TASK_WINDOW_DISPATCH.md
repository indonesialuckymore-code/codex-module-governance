# C10 任务窗口与一级子 Agent 调度

## Boss 得到什么

批准任务后，中央现在能把 C05 的新开/复用建议转成真实 Codex 调度：新开任务、发送给旧任务，或为父任务创建最多 3 个一级子 Agent。默认都使用 Terra。

## 绿黄红

- 绿：共享只读，不争用写入对象，可以并行。
- 黄：包含写入，但 C05 已完成隔离占用，可以在任务包范围内派发。
- 红：重叠写入、依赖不满足、跨模块不明、总账硬停或失联冻结，拒绝派发。

## 为什么是两段式

派发单只表示“允许尝试”。只有 Codex 运行时返回真实任务和 Agent ID，中央才登记总账并把任务推进为 `IN_PROGRESS`。如果只创建了一部分，不能留下“任务已经派发”的假记录。

## Git 任务如何稳定归入项目

中央先按保存项目 ID 创建标准 worktree，然后同时回读项目 ID 和目录。现场实测表明，个别新初始化项目会出现“worktree 目录正确但项目 ID 为空”的状态，此时任务仍可能显示在“最近”。C10 不重建任务，而是把同一任务原生交接到保存项目根目录完成绑定，再交接回原 worktree。只有最终项目 ID 和 worktree 路径同时正确，才登记 `IN_PROGRESS`。

## 子 Agent 回传

子 Agent 只能把事实、证据和阻塞交给父窗口，不能直接向中央宣布整项完成。所有子 Agent 齐全后，父窗口才可统一回传；随后仍走 C06 和 Boss 最终验收。

## 平台不能自动建窗时

中央对已批准派发单运行 `export-fallback`，生成一个可复制的私有任务包。这个降级包不会把任务推进为 `IN_PROGRESS`，不会登记虚假的窗口 ID，也不会改变对象占用；Boss 把内容复制到手工新建的 Codex 任务后，仍须用真实任务 ID 完成 C10 第二阶段确认。

## 验收

运行 `./scripts/verify-c10.sh`。必须证明绿灯并行、黄灯隔离、红灯拒绝、最多 3 个一级 Agent、禁止孙级、部分运行失败不写总账、项目绑定往返修复证据、失联不重派、重复确认和重复回传幂等。
