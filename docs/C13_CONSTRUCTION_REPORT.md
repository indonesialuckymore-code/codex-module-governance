## 验收门槛

- 从新的临时目录取得仓库、安装全部 12 个 Skill，并运行自然语言入口只读冒烟测试。
- 以旧版 `0.12.0` 安装包升级到 `0.13.0`，验证备份存在，再回退到旧版。
- 人为制造升级包损坏，验证原安装摘要不变。
- 用户私有总账放在插件目录外，升级和回退前后字节不变。
- 官方插件和 12 个 Skill 校验器通过；当前用户 Python 已按 Boss 批准安装 PyYAML，可直接运行官方 Skill 校验。
- Codex CLI 从本人私有 GitHub 注册 Marketplace、安装插件、读回版本后再移除测试安装；远端 `main` 再次克隆后复验。
- 个人 Codex 本地 Marketplace 直接指向当前产品源；当前 151 项模块测试全部通过，另有 5 项 C13 安装、失败保全和回退测试。
- Codex 实际 Skill 发现读回显示 12 个模块均来自同一个插件运行副本；原有 5 个同名单独 Skill 已移入仓库外备份，避免双份入口。
- 第一版稳定安装入口固定为私有 Git tag `v0.13.0`，避免新用户无意跟随 `main` 的后续施工变化。

## 剩余风险

- 私有仓库仅对获得 GitHub 权限的用户可安装；公众用户无法直接下载。
- 安装后必须新开 Codex 任务才加载新版 Skill。
- Boss 仍需在新任务的 `/` 菜单确认“施工大纲规划”和“中央处理器”两个中文入口可见；未做这一步前，界面验收保持 `NEEDS_REVIEW`。
- 自动建窗取决于运行表面是否提供真实任务 API；不可用时只降级为复制包，仍需人工新建任务并回传真实 ID。
- C10 已增加保存项目和标准 worktree 归属门禁，但仍需用一个真实新任务确认 Codex 左栏显示在原项目下。
- 本产品仍没有业务外部系统的原生对象级写前锁；实际项目必须继续实时核对唯一写入来源。
