# C00 整个项目施工大纲总设计师

## Boss 得到什么

用一个独立总设计师任务吸收当前对话和已有材料，一次只向 Boss 确认一个关键问题，逐步形成整个项目的总体架构、模块分配、阶段依赖、跨模块接口和施工大纲。大纲冻结后输出 `OUTLINE_HANDOFF`，再由 Codex 唯一中央查重、登记和运营其中明确归属 Codex 的任务。

C00 是可选的整个项目总设计师，不成为第二个中央。Boss 必须为同一大纲版本指定唯一总设计师；可以指定 Fable、C00 或其他规划方。总设计师负责设计，中央负责施工运营，两者不维护同一套详细运行状态。

## 固定边界

- 默认模型：`gpt-5.6-terra`。
- 当前任务已有部分分析时续接上下文，不强制从头重做。
- 只读溯源旧版、半成品、补丁、废弃机制和唯一写入来源。
- 大纲候选任务使用 `P-xx / NOT_REGISTERED`，不伪造 C03 正式编号。
- 不写工程总账、不占用对象、不派工、不施工、不创建 TEST。
- 只有 Boss 明确批准唯一版本后才能冻结为 `FROZEN / NEEDS_REGISTRATION`。
- 真实大纲保存在仓库外私有位置；产品仓库只保存通用 Skill 和空白模板。

## 与现有工作流的接口

```text
C00 整个项目总设计师（Terra）
  → Boss 批准并冻结施工大纲
  → OUTLINE_HANDOFF
  → C09 唯一中央（Sol）
  → C03 只对 CODEX 范围查重、重新编号与正式登记
  → C04 任务包
  → C05 冲突和占用
  → C10 派工
  → C06 独立验收 + Boss 最终决定
```

中央不得机械照抄 C00 候选任务，也不得反向改写冻结大纲。需要改变范围、模块或依赖时，先退回 C00 形成变更版本并重新获得 Boss 批准。
