# C07 裁定请求整理器

## 它解决什么问题

当原任务窗口遇到 Boss 暂时不能直接裁定的阻塞时，C07 把零散问题变成可审查的顾问请求，但不建立第二套任务状态。

```text
原任务窗口阻塞
      ↓
C07 整理事实、未知项、候选方案、风险和不处理后果
      ↓
项目唯一 CURRENT_ADJUDICATION 给建议
      ↓ 只返回 Boss
Boss 选择方案 / 要求补证 / 暂停 / 全部拒绝
      ↓
C07 生成给原任务窗口的决定回传包
      ↓
原窗口按 Boss 决定继续；C07 不自动施工
```

第一次出现这类问题时，从当前中央复制出第一代裁定窗口；后续请求只追加到当前裁定窗口。裁定窗口换代走 C08 交接包，不从头重建上下文。

## 为什么不会形成第三个大脑

- C03 仍是唯一详细任务总账，C07 只复用其中的 `adjudications` 分区。
- 顾问不维护任务状态，不决定下一任务，也不分派窗口。
- C07 从头到尾不改变原任务状态；C08 已负责冻结、续读和受控占用释放。
- 顾问只能在请求包已有方案中推荐，不能悄悄扩大范围。

## 三份不可替代的材料

1. **裁定请求包**：问题、已知事实及证据、未知项、受影响对象、2–5 个方案和延迟后果。
2. **顾问意见**：逐项核对事实，给出推荐、补证要求或无安全建议；只交 Boss。
3. **Boss 决定回传包**：Boss 的选择和给原窗口的指令；它不等于自动执行授权。
4. **中央影响摘要**：只含任务身份、任务影响、依赖影响、成立条件与失效条件；明确排除顾问全文、Boss 理由和讨论过程。

## 永久边界

- 不修改任务状态、对象占用或业务系统。
- 不创建 TEST，不启停生产，不直接给原窗口发送顾问意见。
- 只保存去敏文字和不透明引用；绝对路径、链接、密钥与 Cookie 会被拒绝。
- 如果顾问或 Boss 选择请求之外的方案，C07 拒绝并要求重新整理范围。
- 裁定窗口不能写 C03、派发任务、验收或决定下一波；中央只能读取影响摘要，不能把裁定全文重新塞回上下文。
