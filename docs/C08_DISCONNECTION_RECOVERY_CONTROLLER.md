# C08 失联与恢复控制器

## 它解决什么问题

当任务窗口、一级子 Agent 或 Codex 中央失联时，C08 保住“谁正在做什么、占用了什么、最后一次可信状态在哪里”。它不会因为联系不上就假定任务失败或完成。

C08 现在也处理“还没失联，但中央或裁定上下文已经太长”的计划换代。窗口换掉，逻辑角色、任务事件和现有施工窗口都不断线。

## 角色连续性

- `CURRENT_CENTRAL` 永远只有一个当前窗口；`CURRENT_ADJUDICATION` 最多一个当前窗口。
- 换代前冻结一份交接包：启动图引用、总账摘要、任务/窗口、未处理事件和未完裁定。
- 新窗口校验交接包后才激活；准备与激活之间总账或路由有变化就拒绝。
- 旧窗口降为只读转发器，不能再派工、验收、确认事件或写账。
- 任务窗口先将状态写进私有事件箱，目标写逻辑角色而非聊天 ID，因此中央换代不要求重开任务窗口。
- 任务窗口需要补派子 Agent 时也写 `SUB_AGENT_APPEND_REQUEST` 事件；新中央可继续读取并审查同一私有 C10 请求，但事件本身不派 Agent、不修改任务状态。
- 交接包生成后，任何新事件或事件确认都会使它失效并要求重做，避免继任者漏掉换代缝隙里的回传。

主动计划换代不会自动进入恢复冻结，身份正常的任务窗口可继续施工；真实失联进入恢复冻结后，才按项目级总闸暂停并要求 Boss 决定。单个任务身份不符默认只硬停该任务并保留占用，除非已无法证明项目总账完整性。

```text
发现失联
  ↓ 校验 C03 总账与完整回执链
冻结任务现场 + 保留全部占用
  ↓ Boss 批准新中央接管
恢复治理控制权（仍不恢复业务施工）
  ↓ Boss 决定
保持冻结 / 准备恢复 / 取消任务
  ↓ 独立的释放门
DONE + C06 最终批准，或 CANCELLED + 回滚确认
  ↓ 再次 Boss 批准
只释放该任务自己的治理占用
```

## 三道防重复门

1. C03 进入恢复冻结后，所有非 `C08_*` 总账写入机械拒绝。
2. 每个恢复事件有单调递增的 `recoveryEpoch`，旧接管授权不能覆盖新事件。
3. 每个冻结、接管、决定和释放动作都有不可覆盖回执；相同输入只返回幂等结果。
4. 每次角色切换有独立不可覆盖路由回执；旧角色无法读取或确认当前中央事件。

## 恢复不等于继续施工

- 新中央接管只代表能读取和管理治理账。
- “准备恢复”仍保持任务 `BLOCKED`，实际重新开窗或复用旧窗由 C09/C10 重新经过 Boss、占用和运行确认。
- 失联、接管和恢复决定都不释放占用。
- 只有任务终止后，才能走独立占用释放门。

## 永久边界

- 不从损坏或缺回执的总账猜测恢复状态。
- 不自动重派、不自动恢复业务写入、不创建 TEST。
- 释放的是 C03/C05 治理占用，不是外部文件、Base、workflow 或服务的原生锁。
- 取消任务释放前必须确认回滚完成、没有未完成业务写入；`DONE` 释放必须验证 C06 最终批准。
