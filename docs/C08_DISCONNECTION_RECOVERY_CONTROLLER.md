# C08 失联与恢复控制器

## 它解决什么问题

当任务窗口、一级子 Agent 或 Codex 中央失联时，C08 保住“谁正在做什么、占用了什么、最后一次可信状态在哪里”。它不会因为联系不上就假定任务失败或完成。

```text
发现失联
  ↓ 校验 C03 总账与完整回执链
冻结任务现场 + 保留全部占用
  ↓ Boss 批准新中央接管
恢复治理控制权（仍不恢复业务施工）
  ↓ Boss 决定
保持冻结 / 准备恢复 / 取消任务
  ↓ 独立的释放门
DONE + C06 最终批准，或 CANCELLED + 回滚确认
  ↓ 再次 Boss 批准
只释放该任务自己的治理占用
```

## 三道防重复门

1. C03 进入恢复冻结后，所有非 `C08_*` 总账写入机械拒绝。
2. 每个恢复事件有单调递增的 `recoveryEpoch`，旧接管授权不能覆盖新事件。
3. 每个冻结、接管、决定和释放动作都有不可覆盖回执；相同输入只返回幂等结果。

## 恢复不等于继续施工

- 新中央接管只代表能读取和管理治理账。
- “准备恢复”仍保持任务 `BLOCKED`，实际重新开窗或复用旧窗由 C09/C10 再审查。
- 失联、接管和恢复决定都不释放占用。
- 只有任务终止后，才能走独立占用释放门。

## 永久边界

- 不从损坏或缺回执的总账猜测恢复状态。
- 不自动重派、不自动恢复业务写入、不创建 TEST。
- 释放的是 C03/C05 治理占用，不是外部文件、Base、workflow 或服务的原生锁。
- 取消任务释放前必须确认回滚完成、没有未完成业务写入；`DONE` 释放必须验证 C06 最终批准。
