# 运行中纠偏：候选源码协议

状态：PARTIAL，候选源码已接通留证、局部暂停、通信进度、生效核验登记、恢复资格和恢复后的版本验收；真实运行、升级及自动增量交接仍未验收，不具备本轮安装条件。只在隔离夹具验证，不手改账本解除暂停。

## 唯一归口与适用范围

- C03 原任务的 `directionCorrections` 保存连续版本、原因、Boss 决定、指令引用、被替换与保留要求，以及当前承接窗口的线程/代际。只保存不透明引用，业务正文留在私有证据。
- 仅用于批准合同不变时调整执行做法；目标、范围、风险或验收要求实质改变，必须先走相应设计与批准变更。本字段不是权限扩大入口，引用存在也不证明 Boss 原话的真实性。
- 原任务状态、身份、成果、占用和证据保留；不新建“纠偏任务”、第二中央或第二总账。不把局部纠偏写成项目全局硬停。

## 当前可验证行为

由当前中央运行 C03 `record-correction --task-id ID --correction-id ID --expected-revision N --instruction-ref REF --reason-ref REF --boss-decision-ref REF --retain-ref REF --supersede-ref REF`。保留/替换引用可重复选项；不能互相重叠。全局仍需正确私有目录、项目、writer 和 caller。

版本从 1 开始，首次 expected-revision 为 0。同编号同请求重试不写账；同编号不同内容拒绝；旧父版本不能覆盖新方向。需要再次调整时在最新版本上追加，新要求不会擦掉历史。已结束任务不能使用此入口。

输出 `PAUSE_REQUESTED` 是请求状态，`runtimeInterrupted=false` 明确未证明平台已中断。C03 `read-correction --task-id ID` 可获得当前版本、`messageRequests` 和从 C14 原回执派生的 `communication`；区分未入队、队列中、投递成功、收件确认、窗口报告结果及结果通知确认。不需要另抄任务材料。

`messageRequests` 是稳定编号的 C14 私有请求，不是已经发送的通知。对每个已登记窗口，按 C14 链路入队、原生发送、记录回执、窗口确认和结果回传。指令类型 `DIRECTION_CORRECTION` 必须匹配当前版本、摘要、指令引用和窗口代际。窗口换代后不得静默转投，先重新核对并追加绑定当前窗口的新版本。

- 已被新版取代的纠偏不能再发送、确认或按旧指令报告执行结果。
- 待纠偏任务的普通施工/重试/验收指令暂停投递；取消通知仍可传递，但通知本身不授权删除或撤销外部操作。
- C03 受影响任务不能重新 READY/IN_PROGRESS/DONE、登记新施工窗口或子 Agent、扩大 WRITE 占用；可保留结果、登记证据和读取状态。其他任务不因这个局部信号自动停工。
- C05 占用检查和 C10 准备/确认/补派检查暂停状态；C03 在写入时再次防止继续开工、补派和 C06 状态写入。旧完成信号可以留存，C06 不得按旧要求给出通过结论或以既有通过结果完成最终批准。

这些是受治理入口的约束，不是操作系统写入拦截。已在运行的命令、平台已经接受的派发和外部写入必须另行确认，必要时由可用原生控制停止并回读。不能声称旧操作已经撤销。

## 生效核验与恢复

`ACKNOWLEDGED` 仅代表看到消息，`APPLIED` 仅代表任务报告。所有绑定窗口均报告 APPLIED，且各结果通知真实投递并被中央确认后，才是 `readyForVerification=true`。程序核对信封、任务/窗口代际、结果、投递和确认关联，不拿单个状态文件当闭环。尚未开窗的任务没有通信对象，但仍需核验当前执行安排与在途状态。父窗口的停止和影响证据须包括其子 Agent，不可只看父窗口一句回复。

当前中央实际读回并核验后，在私有目录生成 JSON 核验记录，运行 C03 `verify-correction --task-id ID --verification 私有文件`。核验文件字段：

- `recordType=C03_DIRECTION_APPLICATION_VERIFICATION`；`verificationId`、`projectId`、`taskId`、`correctionId`、整数 `revision`、`correctionDigest`、`verifiedByThreadRef`。
- `correctionDigest` 对应 C03 当前纠偏的 requestDigest，它是纠偏引用与元数据摘要，不是业务指令正文哈希。`instructionRef` 必须指向不可覆盖的私有指令版本；不得在同一引用下偷换正文。
- `checks` 恰含五项：`CURRENT_INSTRUCTION_APPLIED`（当前指令已落实）、`RETAINED_REQUIREMENTS_PRESERVED`（保留要求未丢失）、`SUPERSEDED_WORK_STOPPED`（被替代工作已停止）、`IN_FLIGHT_EFFECTS_RECONCILED`（已发出操作及影响已核对）、`APPROVED_CONTRACT_UNCHANGED`（批准合同没有实质变化）。每项含 `check`、`status=PASS` 和非空 `evidenceRefs`。
- `evidence` 为非空数组，每项含不透明 `reference`、私有文件 `file` 与文件实际字节的 `sha256`。检查引用必须指向数组中存在的证据；同一真实证据可以支撑多个检查，不为凑五项制造五份文件。

程序验证记录的身份、当前版本、通信完整性及证据文件存在/摘要一致；**不会从哈希自动判断业务真的改对**。五项 PASS 必须来自实际读回，不得为解锁填表。核验者是当前中央且不得同时是该任务执行窗口；具体成果仍另走隔离 C06，不新增低风险自动 DONE 权限。

核验在 C03 锁内重查最新纠偏并追加不可覆盖的 `directionVerifications`，解除该任务治理暂停，返回 `VERIFIED_FOR_RESUMPTION`。不自动改任务状态、不重建窗口、不冒称运行时已停止或已重新启动。按原授权和正常派发/继续入口接续；不要求 Boss 再次批准同一个纠偏。新纠偏立即形成新暂停，旧核验不能解除新版本。换代后新中央可复用已确认通信事实，但须以当前身份核验；旧中央不能放行。

已核验记录的查询以 `communicationSource=SEALED_VERIFICATION` 标明历史快照；任务完成或窗口换代不抹掉历史证明，也不把历史快照称为实时读回。

## 恢复后的旧版本保护

- 普通 C14 指令入队时绑定当时的方向版本；纠偏前积压的施工指令在恢复后仍拒绝投递。需要继续的工作重新按当前指令生成消息，不改旧消息。
- C10 新派发/补派单携带 `directionContext` 和当前指令引用；已有旧派发单不能重复使用、确认或导出手工备用包。新派发单的任务包必读材料和原生动作提示带当前指令；不得只传旧 executionSequence。
- 经纠偏任务的 C06 回传须带 `directionContext={revision,digest}`，对应当前纠偏版本和 requestDigest。C08 保留并校验该字段；C06 评审与最终批准都核对当前版本。未纠偏历史任务仍按无字段的旧格式处理。
- 旧完成信号和旧证据可保存，但不能给旧材料补一个新版号就当成重新验收。须实际核对新要求及保留要求，重新生成当前版本的回传和独立决定；旧通过结论不会因暂停解除而恢复效力。
