# 回传与独立验收器

严格分离任务窗口自报完成、中央独立验收和 Boss 最终裁定。只写 Codex 私有治理材料及 C03 总账，不修改业务系统。

## 验收顺序

1. 先确认 `returnTicketId` 已取得 C08 的 `TASK_EVENT_QUEUED` 投递回执；缺票据、事件、摘要哈希或投递回执一律是 `LOCAL_REPLY_ONLY / OUTBOX_PENDING`，不得验收。
2. 确认中央已用票据登记 C03 完成信号，任务处于 `NEEDS_REVIEW`，回传窗口与任务一致。
3. 确认本次可由 Boss 单项授权，或由 Boss 已批准的 `AUTO_QUEUE_AND_VALIDATE_WITHIN_APPROVED_SCOPE` 回传政策覆盖；政策只免除重复“是否送验收”的询问，不免除最终 `DONE`。
4. 独立读回十类证据：改前、改后、正例、反例、幂等、回滚、日志历史、上游、下游、TEST/对象编号。
5. 核对是否越界、出现平行机制、未知写入方、扩大权限、未解释错误、重复数据或阻断性剩余风险。
6. 生成不可覆盖验收决定并记录到 C03。只有全部证据通过时输出 `PASS_PENDING_BOSS_APPROVAL`，任务仍保持 `NEEDS_REVIEW`。
7. 验收窗口把结果票据交回中央；中央只接收任务、验收结论和回执，不接收施工原文。`PARTIAL`、`CONFLICT`、`BLOCKED` 或通过后的最终批准才提醒 Boss。
8. Boss 最终批准后，使用同一验收决定完成任务；C06 是唯一可绕过普通 `DONE` 禁止门槛的路径。
9. 写入 `DONE` 的同一次原子变更还要结束该任务的活动子 Agent，并更新窗口：首次任务完成后标记 `AVAILABLE_FOR_REUSE`，第二次任务完成后标记 `RETIRED`。
10. 同时在不可变最终裁定中写入 `successorDispatch`。批准时为 `required=true`，中央必须自动重算和派发原启动图内的新近合格任务；拒绝时不触发续派。

## 结论规则

- `PASS_PENDING_BOSS_APPROVAL`：全部独立证据通过，等待 Boss 最终批准。
- `NEEDS_REVIEW`：证据缺失或未独立读回，任务不完成。
- `PARTIAL`：已有失败证据、回滚不可执行、未解释错误或阻断风险。
- `CONFLICT`：范围越界、平行机制、未知写入方、权限扩大或重复数据，登记硬停。

## 永久边界

- 任务窗口和子 Agent 只能提交材料，不能写验收结论或 `DONE`。
- 中央验收通过也不能代替 Boss 最终批准。
- 自动续派不能扩大原启动图授权；范围、对象、依赖、风险或项目绑定变化仍须把变化部分交 Boss。
- 只保存去敏摘要和不透明证据引用，不保存真实客户、财务、密钥、Cookie、链接或绝对路径。
- 不创建 TEST、不修改业务对象、不启停生产入口、不释放 C05 占用；占用释放与恢复由 C08 负责。
