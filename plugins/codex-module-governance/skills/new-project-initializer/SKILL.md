# 新项目初始化器

这是 Codex 模块的 C02 能力。它只回答“这个项目是否可以安全登记”，不管理任务、窗口、证据、对象占用或跨模块进度。那些职责必须等待 C03 及后续能力，不得用本 Skill 绕开。

## 先确认的业务信息

新项目登记前，先向 Boss 确认或建议以下四项：

1. 项目显示名称：给人看的名称。
2. 项目编号：英文小写、数字和连字符组成的唯一编号；可由显示名称提出建议，但由 Boss 确认。
3. 范围摘要：一句话说明这次准备解决什么，不填真实客户、账务、账号或密钥。
4. 私有数据目录：用户选择、仓库外且不在任何 Git 工作树中的目录。

若任何一项缺失，只询问最关键的一项，不自行猜测真实项目范围或数据位置。

## 标准动作

1. 先运行只读查重。查重会检查同编号、同名和近似名称项目；不会写入任何文件。
2. 如果发现同名、近似或旧项目，报告候选项目和建议：复用、迁移评估或人工裁定。此时不得创建第二张项目卡。
3. 只有 Boss 明确说“批准建档”或同等明确意思，且查重为可新建时，才运行写入动作。
4. 写入动作只创建私有项目启动卡、初始化回执和项目索引；不得派发任务、创建 TEST、建立工程总账、改业务系统或上传文件。
5. 回报创建结果时，用业务语言说明项目编号、卡片状态、下一道门槛和剩余风险。项目启动卡状态只能是 `PROJECT_REGISTERED`，不能报 `DONE`。

## 命令模板

先查重：

```bash
python3 plugins/codex-module-governance/scripts/initialize_project.py \
  --data-root "/用户选择的私有目录" \
  --project-id "approved-project-id" \
  --display-name "项目显示名称" \
  --scope-summary "不含业务数据的一句话范围" \
  --dry-run
```

Boss 批准后建档：

```bash
python3 plugins/codex-module-governance/scripts/initialize_project.py \
  --data-root "/用户选择的私有目录" \
  --project-id "approved-project-id" \
  --display-name "项目显示名称" \
  --scope-summary "不含业务数据的一句话范围" \
  --apply
```

如用户已在私有位置保存模块配置，也可以把 `--data-root` 换为 `--config "/私有配置路径/module-config.json"`。配置和生成数据都不得进入产品仓库。

## 永久边界

- 不把项目索引称为工程总账，不用它记录任务、证据或对象锁。
- 不创建或修改真实业务数据、TEST、生产配置、账号、密钥、Cookie 或权限。
- 不允许数据目录处于产品仓库、产品仓库父/子目录或任何 Git 工作树。
- 发现索引损坏、初始化锁存在或重复项目时硬停，保留现场供 Boss 处理。
- 不因项目卡已创建而宣布项目可施工；下一步必须等待 C03 的总账归口与状态机裁定。
