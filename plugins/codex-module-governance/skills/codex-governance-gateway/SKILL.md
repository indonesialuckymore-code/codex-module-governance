# Codex 治理自然语言入口

把 Boss 的一句业务话翻译成 C09 标准请求，再交给 `central-construction-controller`。本 Skill 是前台入口，不是第二个中央。

## 固定顺序

1. 先确认当前私有数据目录和项目；只有一个项目时可自动沿用，多个项目时只问项目编号。
2. 一次只识别一个治理动作。包含多个动作时，请 Boss 拆开，不自行决定顺序。
3. 把请求分类为：
   - `READ_ONLY`：只看，不写总账、不派发；
   - `PREPARE`：只准备草案或建议，等待 Boss 批准；
   - `APPLY`：Boss 已明确批准当前对象，但仍必须经过 C09 和下游能力自身门禁。
4. 只有唯一候选时才自动补齐任务、任务包、验收、恢复事件或窗口编号；有多个候选时只问一个最关键问题。
5. 将标准请求交给 C09；报告目标模块、是否需要后续批准、影响范围、验收方法和剩余风险。

## 口语入口

| Boss 可以说 | 入口含义 |
|---|---|
| “启动新项目” | C02 查重并准备建档；缺项目编号时先问 |
| “初始化项目总账” | C03 准备或建立唯一详细总账 |
| “查看总账和下一个候选任务” | C03 只读 |
| “生成任务包，不要派发” | C04 准备草案 |
| “检查冲突，判断新开还是沿用窗口” | C05 检查占用 |
| “批准派发这个任务包” | 转 C10；真实运行仍须两段式确认 |
| “任务完成了，开始验收” | C06 独立验收，不直接写 `DONE` |
| “这个问题我不能裁定，请中央后台给意见” | C07 建议只回 Boss |
| “窗口失联了，先冻结现场” | C08 冻结并保留占用 |
| “撤销任务” | 正常状态转 C03 记录撤销请求并保留必要占用；失联冻结时由 C09 优先转 C08 |
| “固定/替换一个外部 Skill” | C11 登记和审查，不自动安装 |

## 含糊批准

- 单独一句“批准”“可以”“同意”只有在当前对话紧邻的上一条提议中恰好有一个待批准动作和一个明确对象时才能绑定；否则必须追问批准哪个项目、任务或待执行动作。
- 同一句既说“只看”又说“批准执行”时，必须让 Boss 二选一。
- 不从旧对话猜测授权对象；当前请求必须能唯一绑定项目和治理对象。

## 数据与执行边界

- 不保存 Boss 的原始口语，只输出摘要值；发现密码、密钥、Cookie、令牌或验证码时要求删除后重述。
- 不创建自己的任务表、项目状态或授权记录；C03 仍是唯一详细总账，C09 仍是唯一中央路由器。
- 翻译成功不等于下游执行成功；任务派发、验收、恢复和 Skill 启用仍走各自闸门。
- 不直接改业务系统、不创建 TEST、不启停生产入口、不自动安装外部 Skill。

需要确定性核对时运行：

```bash
python3 plugins/codex-module-governance/scripts/natural_language_gateway.py \
  --data-root <私有数据目录> interpret --text "查看当前总账"
```
