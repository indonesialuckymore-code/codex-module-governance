# 失联与恢复控制器

复用 C03 `recovery` 分区与不可覆盖回执，禁止建立第二套恢复状态。

## 计划换代与不断线

1. 中央和裁定窗口都使用逻辑角色：`CURRENT_CENTRAL`、`CURRENT_ADJUDICATION`，任务窗口不绑定某个聊天 ID。
   模型不是角色条件；继任窗口可以使用不同模型。初始化、换模型或继任确认时读取[模型选择与真实运行记录](../../references/runtime-model-policy.md)，不得为换模型重新创建角色或撤销批准。
2. 换代前生成交接包，保存角色路由快照、总账摘要、未处理事件和待裁定引用；普通材料变化时按角色连续性协议生成关联更新包，不覆盖原包或因此重开继任窗口。
3. 计划换代时可先用原生 `fork_thread` 复制当前中央或裁定窗口的已完成对话；这只提供阅读上下文，不代表接管成功。新窗口读回同一交接包并校验摘要后才激活为下一代；同一角色始终只有一个当前窗口。
4. 旧窗口立即降为只读转发器，不能继续派工、裁定、验收或写账。
5. 任务窗口先把状态写入私有事件箱，再由 C14 向当前中央发送原生消息；施工交付为 `submit-return → returnTicketId → TASK_EVENT_QUEUED → C14 delivery → MESSAGE_ACKNOWLEDGED`。C08 票据、摘要哈希和投递回执是回传事实，C14 收件确认才证明当前中央已收到；聊天文字只能是提醒。中央换代期间未确认消息会重新解析 `CURRENT_CENTRAL`，事件和票据仍由新中央续读。`SUB_AGENT_APPEND_REQUEST` 也是持久事件：它只通知中央审查私有 C10 补派请求，不自行创建 Agent 或改变任务状态。
6. 制包后新增或确认事件时，当前中央运行 refresh-handover；继任者读回更新和最新包摘要后才激活。未变化时复用原包，刷新结果 snapshotCurrent=false 时不能使用；不得把补读改成 Boss 逐轮批准。
7. 一句话交接按角色连续性协议的原生执行顺序完成 prepare-successor、真实建窗/绑定、继任读回、激活和打开留证。旧窗口只读；原生 handoff_thread 只移动环境，不能冒充中央接管。调用结果不明先对账，不重开窗口。候选已验证回执握手和路由提交前后恢复；真实平台操作仍须现场回读，不能用隔离测试代替。

主动计划换代不等于失联恢复：前者不自动冻结身份正常的任务窗口，也不改变 C03 `recovery`；后者一旦进入冻结状态，才按项目级恢复总闸暂停施工。

详细操作见 `../../references/central-construction/role-continuity.md`。

## 处理顺序

1. 校验 C03 当前总账和完整回执链；总账或回执不完整时只报告 `RECOVERY_BLOCKED`，不得重建猜测状态。
2. 记录失联事件并冻结原任务、窗口或子 Agent；保留全部对象占用，不派新窗口、不恢复业务施工。
   - 若 C10 在复用旧窗口前失败，窗口可能处于 `RESERVED_FOR_REUSE`；C08 用 `reservedForTaskId` 识别该尚未真正开始的任务，允许把“保留预留继续重试”或“Boss 授权取消”纳入同一受控恢复，禁止直接删除预留字段。
3. 生成恢复快照：任务状态、窗口、子 Agent、占用、完成信号、裁定和证据引用，以及最后有效回执。
4. 新中央接管前校验 Boss 授权、前一恢复 epoch 和快照摘要；接管只恢复治理控制权。
5. 对任务恢复、取消或占用释放分别处理，不把三者合并成一个动作。
6. 只有任务经 C06 成为 `DONE`、无相关冲突且 Boss 明确批准释放时，才删除该任务自己的治理占用声明。

## 结论边界

- `FROZEN_AWAITING_RECOVERY`：失联已登记，现场冻结，占用保留。
- `CENTRAL_CONTROL_RECOVERED`：新中央可续读治理账，但业务施工仍未恢复。
- `RECOVERY_BLOCKED`：总账、回执、授权、epoch 或对象归属无法确认。
- `OCCUPANCY_RELEASED_AFTER_DONE`：只释放已完成任务自己的治理占用，不影响其他声明。

## 永久禁止

- 不因超时、失联或窗口不可见自动释放占用。
- 不从残缺账本推测任务完成，不重复派发，不重复处理完成信号。
- 不把聊天复制或模型压缩摘要当作交接事实源；交接包与事件箱才是续接依据。
- 不把 `ACKNOWLEDGED` 当成验收通过：它只说明中央已取得队列索引。回传票据仍须经单槽独立验收和 Boss 最终批准才可能 `DONE`。
- 不自动恢复业务施工、不创建 TEST、不修改业务对象或生产入口。
- 只有 `codex-module-central` 可写 C08 记录；Boss 授权必须以不透明引用保存。
- 私有恢复材料不得进入 GitHub，不得包含绝对路径、链接、密钥、Cookie、客户或财务数据。
