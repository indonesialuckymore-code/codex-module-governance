# 失联与恢复控制器

复用 C03 `recovery` 分区与不可覆盖回执，禁止建立第二套恢复状态。

## 计划换代与不断线

1. 中央和裁定窗口都使用逻辑角色：`CURRENT_CENTRAL`、`CURRENT_ADJUDICATION`，任务窗口不绑定某个聊天 ID。
2. 换代前生成交接包，冻结角色路由快照、总账摘要、未处理事件和待裁定引用；快照变化就作废重做。
3. 新窗口读回同一交接包并校验摘要后才激活为下一代；同一角色始终只有一个当前窗口。
4. 旧窗口立即降为只读转发器，不能继续派工、裁定、验收或写账。
5. 任务窗口先把状态写入私有事件箱，再提醒当前中央；中央换代期间即使消息没送达，事件仍由新中央续读。
6. 制包后新增或确认任何事件都会让交接包失效；先重做交接包，再激活继任者。

主动计划换代不等于失联恢复：前者不自动冻结身份正常的任务窗口，也不改变 C03 `recovery`；后者一旦进入冻结状态，才按项目级恢复总闸暂停施工。

详细操作见 `../central-construction-controller/references/role-continuity.md`。

## 处理顺序

1. 校验 C03 当前总账和完整回执链；总账或回执不完整时只报告 `RECOVERY_BLOCKED`，不得重建猜测状态。
2. 记录失联事件并冻结原任务、窗口或子 Agent；保留全部对象占用，不派新窗口、不恢复业务施工。
3. 生成恢复快照：任务状态、窗口、子 Agent、占用、完成信号、裁定和证据引用，以及最后有效回执。
4. 新中央接管前校验 Boss 授权、前一恢复 epoch 和快照摘要；接管只恢复治理控制权。
5. 对任务恢复、取消或占用释放分别处理，不把三者合并成一个动作。
6. 只有任务经 C06 成为 `DONE`、无相关冲突且 Boss 明确批准释放时，才删除该任务自己的治理占用声明。

## 结论边界

- `FROZEN_AWAITING_RECOVERY`：失联已登记，现场冻结，占用保留。
- `CENTRAL_CONTROL_RECOVERED`：新中央可续读治理账，但业务施工仍未恢复。
- `RECOVERY_BLOCKED`：总账、回执、授权、epoch 或对象归属无法确认。
- `OCCUPANCY_RELEASED_AFTER_DONE`：只释放已完成任务自己的治理占用，不影响其他声明。

## 永久禁止

- 不因超时、失联或窗口不可见自动释放占用。
- 不从残缺账本推测任务完成，不重复派发，不重复处理完成信号。
- 不把聊天复制或模型压缩摘要当作交接事实源；交接包与事件箱才是续接依据。
- 不自动恢复业务施工、不创建 TEST、不修改业务对象或生产入口。
- 只有 `codex-module-central` 可写 C08 记录；Boss 授权必须以不透明引用保存。
- 私有恢复材料不得进入 GitHub，不得包含绝对路径、链接、密钥、Cookie、客户或财务数据。
