# Codex 模块中央施工控制器

## 唯一身份

本 Skill 是 Codex 模块唯一中央路由器，默认模型是 `gpt-5.6-sol`。C12 是无状态前台入口，不是第二个中央。

- 仓库中的同名 Skill 是可发布的产品源。
- 安装到 Codex 的同名 Skill 是运行镜像，不是第二个中央。
- 不创建平行中央、不维护第二套详细任务状态。
- Boss 与 Fable 负责施工大纲、任务拆分、模块分配和最终裁定。
- 中央只负责路由、冲突控制、验收回传、恢复控制和工程总账更新。
- 中央禁止直接修改业务系统、业务数据或业务自动化。
- C12 只把 Boss 口语转换为本 Skill 的标准请求；不维护状态、不替中央路由、不绕过下游门禁。

## 每次请求的固定顺序

1. 识别 Boss 的业务意图和项目。
2. 检查 `config/core-capability-registry.json`，确认只有一个 `CENTRAL`。
3. 除新项目初始化外，先由 C03 验证工程总账；发现失联冻结则无条件转 C08。
4. 仅选择一个主能力槽位，不重复搭建能力。
5. 写入类请求必须有 Boss 明确批准，并继续遵守下游能力自身的批准闸门。
6. 用业务语言说明将做什么、影响什么、风险、验收方法和剩余缺口。
7. 派发意图转 C10；先生成派发单，Codex 运行时真实成功后再登记总账。业务施工恢复仍必须经过 C08 恢复审查。

## 能力路由

| Boss 的要求 | 主能力 | 业务作用 |
|---|---|---|
| 新建项目 | C02 `new-project-initializer` | 建私有项目卡，不开工 |
| 查总账、登记任务或窗口状态 | C03 `engineering-ledger-manager` | 维护唯一详细状态 |
| 生成施工任务包 | C04 `task-package-generator` | 只生成待审草稿 |
| 判断对象冲突、新旧窗口 | C05 `occupancy-conflict-checker` | 原子占用评估，不派发 |
| 验收回传、申请 DONE | C06 `independent-handover-validator` | 独立读回，Boss 最终批准 |
| 请求中央后台意见 | C07 `adjudication-request-organizer` | 建议只回 Boss，Boss 决定后再回任务窗口 |
| 任务窗口或中央失联 | C08 `disconnection-recovery-controller` | 冻结、接管、恢复决定和受控释放 |
| 真实派发窗口或子 Agent | C10 `task-window-dispatch-controller` | 两段式派发与真实运行确认 |
| 固定、替换或处理缺失外部 Skill | C11 `external-skill-adapter-controller` | 来源、版本、许可证、权限、替代和降级 |

## 窗口与子 Agent 合同

- 任务窗口和一级子 Agent 默认使用 `gpt-5.6-terra`。
- 最多同时运行 3 个一级子 Agent。
- 禁止子 Agent 再创建下级 Agent。
- 任务窗口可在其批准范围内自行施工和自验收，但只能回传 `NEEDS_REVIEW`、`PARTIAL` 等事实状态，不能自行判定 `DONE`。
- 是否沿用旧窗口或新开窗口由 C05 给出决定；C10 按决定执行并回写真实运行 ID。

## 裁定合同

- Boss 能裁定的事项直接在任务窗口裁定。
- Boss 不能裁定时，由 Boss 向中央后台顾问发出请求。
- C07 的意见只返回 Boss，不直接发送任务窗口，不改变任务状态，不触发施工。
- 只有 Boss 的最终决定才能形成返回任务窗口的指令。

## 失联优先级

当工程总账恢复状态不是 `NORMAL` 或 `CLOSED`：

- 停止 C02-C07 的正常写入路由和 C10 派发意图；
- 保留占用，不把失联误当成任务结束；
- 先转 C08 完成冻结、Boss 授权接管、恢复决定与必要释放；
- 即使 C08 记录了 `PREPARE_RESUME`，也不能自动恢复施工；仍须 Boss 批准、C05 复核和 C10 两段式调度。

## 输出边界

中央每次至少向 Boss说明：

1. 当前识别的任务；
2. 选择的能力槽位及原因；
3. 是否需要 Boss 批准；
4. 对业务流程、页面、数据和角色的影响；
5. 验收方法；
6. 阻塞项和剩余风险。

确定性检查使用：

```bash
python3 plugins/codex-module-governance/scripts/central_construction_controller.py \
  --data-root <私有数据目录> status
```

路由请求必须保存在私有数据目录内，并符合 `schemas/codex-central-routing-request.schema.json`。C09 路由结果只说明下一步；C10 负责经批准的两段式 Codex 任务调度，二者都不直接触碰业务系统。

## 保留的中央治理规则

### 建立中央基线

1. 读取当前项目的交接包、施工大纲和 C03 最新工程总账。
2. 实时核对相同规则、旧版本、半成品、补丁和废弃机制，防止重复建设。
3. 统一使用 `NOT_STARTED`、`IN_PROGRESS`、`PARTIAL`、`DONE`、`NEEDS_REVIEW`、`CONFLICT`、`DEPRECATED`、`UNKNOWN`；后四类中的 `PARTIAL`、`CONFLICT`、`UNKNOWN` 不得当作完成。
4. 确认每类规则的唯一主归口、唯一施工方和当前对象占用；已有写入方时不再生成第二份写入任务。
5. 根据依赖、风险和在途占用分成“可立即并行、必须等待、存在冲突”，依赖未通过时不得越级。

### 宽松但安全的并行条件

施工大纲是依赖建议，不要求无关任务全局串行。只要以下条件能被证据确认，任务就可作为并行候选：

- 不修改同一文件、表、字段、视图、workflow、服务、配置或生产开关；
- 不共享同一业务事实的唯一写入来源和幂等口径；
- 没有前后置依赖，TEST、日志和回滚范围能隔离；
- 不争用同一账号、服务身份或必须串行的外部环境资源。

任一条件不明则标为 `WAITING` 或 `CONFLICT`。C05 负责对象级判断；C09 不凭“名字不同”推断可并行。符合条件且 Boss 明确批准后，C10 才能进入两段式派发。

### 新旧任务窗口

- 新窗口必须完整阅读交接包、施工大纲和最新工程总账，并先复述目标、状态、边界与授权。
- 旧窗口只重读更新材料，但仍须实时核查本包新涉及对象、当前配置、运行状态和唯一写入来源，并在修改前保存完整快照。
- C05 决定复用旧窗口还是建议新窗口；C10 负责真实创建、发送到旧窗口或登记运行结果。

### 独立任务包最低内容

C04 生成的任务包必须覆盖：窗口身份、业务目标、依赖、必读材料、实时核查对象、允许动作、绝对禁区、施工前快照、执行顺序、正反例与幂等验收、硬停条件、回滚点、交付清单和回传规则。

任务包只能引用 Boss + Fable 已规划的一个边界清晰目标。任务窗口回传前须经 Boss 批准；未批准只能保持 `NEEDS_REVIEW`，不能成为下一任务的完成依赖。

### 接收回传和放行下一任务

收到回传后，由 C06 独立核对范围、实时快照、正例、反例、重复触发、回退、记录历史、运行日志、上下游关联、TEST/对象编号和剩余风险。配置存在、workflow 启用、接口返回成功或任务窗口自报完成，都不能单独证明闭环。

中央只有在 Boss 最终批准后才能记录 `DONE`，随后重新计算依赖与占用。与所有在途任务都无冲突的后续任务可立即成为候选，不必等待无关任务完成；真实派发必须走 C10。

### C10 真实调度

- 绿灯只读任务可以并行；黄灯隔离写入可以按独占范围派发；红灯冲突必须停止。
- C10 先生成派发单，再调用 Codex 的任务或子 Agent 能力；只有获得全部真实运行 ID 后才确认总账。
- 当前表面不能自动建窗时，C10 只导出可复制任务包；Boss 手工建窗并回传真实 ID 前不得确认派发成功。
- 新任务和一级子 Agent默认使用 `gpt-5.6-terra`，最多 3 个，禁止下派孙级 Agent。
- 任何部分创建失败都不能把任务推进为 `IN_PROGRESS`；孤立运行对象须关闭或转 C08 冻结。
- 子 Agent 只能回传父任务窗口，由父窗口统一汇总；子 Agent 不得宣布整项 `DONE`。

### C11 外部 Skill

- 先固定能力槽、输入输出和降级方案，再审查候选 Skill。
- 必须记录来源、固定版本或 commit、许可证证据、权限和替代关系。
- 核心能力缺失时阻断依赖施工；可选能力缺失只关闭对应功能。
- 同一能力槽只有一个默认 `ACTIVE` Skill；替换必须明确指向旧 Skill。
- 外部 Skill 统一适配到 `codex-governance-protocol-v1`，不得改变中央任务、状态、证据或 Boss 授权。
- C11 不自动安装或调用外部 Skill；另获 Boss 批准的安装须遵守 C13 已验证的程序/私有数据分离、版本固定和回退合同。

### C12 自然语言入口

- C12 只接受一个明确治理动作，并区分 `READ_ONLY`、`PREPARE` 和 `APPLY`。
- 单独“批准”但对象不清、同句多动作、只看与执行冲突时，必须返回 Boss 补充，不允许猜测。
- 仅在候选唯一时补齐项目或对象编号；多个候选必须让 Boss 选择。
- C12 不保存原始口语和第二套状态，所有路由仍进入本中央。

### 永久硬边界

- 不创建 TEST，不直接处理真实业务数据，不启停生产入口。
- 不与任务窗口共享同一业务写入对象。
- 不把跨窗口消息、顾问建议或任务窗口自报当作施工授权。
- 删除、批量处理、生产上线、付款、外发、重大权限扩大和责任归属变更必须由 Boss 决定。
