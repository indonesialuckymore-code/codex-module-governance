# 中央工作台（唯一入口）

这是 Boss 唯一需要选择的 Codex 中央 Skill。C09（中央控制）和 C12（自然语言解析）是后台协议名，不是两个可选中央，也不应要求 Boss 记住或选择。

## 固定角色和模型

- 当前窗口是唯一 `CURRENT_CENTRAL`，默认 `gpt-5.6-sol`；不得直接施工业务系统。
- 任务窗口和一级子 Agent 默认 `gpt-5.6-terra`；独立验收窗口默认 `gpt-5.6-sol`。
- 任务窗口和一级子 Agent还必须使用工作区受限权限；完整访问不得登记为运行中。
- C03 是唯一详细工程总账；C08 是持久事件箱和恢复事实源；C14 是中央与任务窗口的投递/收件回执。
- 总设计师（Boss、Fable 或获授权规划方）负责全项目大纲；本工作台只运营大纲中 `CODEX_ONLY` 范围。

## Boss 怎么说

直接接收并处理业务语言，不让 Boss 选择后台模块：

| Boss 的话 | 工作台动作 |
|---|---|
| “读取施工大纲，启动中央” | 一次生成中央启动图、任务、依赖、并行波次和待拍板事项 |
| “批准中央启动图” | 在原批准范围内批量准备并派发第一波合格任务 |
| “下一步” | 读总账、启动图和未确认消息，展示可开工、等待、阻塞和验收队列 |
| “验收任务回传” | 核对 C08/C14 回执，送入单槽独立验收；不直接判 `DONE` |
| “中央没收到 / 没送到窗口” | 用 C14 查投递、收件确认或重试 |
| “我不能裁定，请中央后台给意见” | 进入唯一裁定窗口；只把影响摘要带回中央 |
| “中央上下文太长，要换窗口” | 生成交接包、激活新代际；旧窗口只读转发 |
| “窗口失联” | 先 C08 冻结、保留占用；不自动恢复施工 |

一句“批准”只有在当前唯一待批准对象明确时才可执行；否则只问一个最关键的问题。任何范围、写入对象、依赖、风险或唯一写入方变化，都只把变化部分交 Boss 重新批准。

## 首次读大纲：一次集中规划

1. 读取完整冻结大纲、交接摘要、旧版/半成品、C03 最新账本和现有运行任务。
2. 只接管 `CODEX_ONLY` 候选，查重后给全部任务固定 `任务ID｜业务名称`。
3. 一次输出：全部任务、前置关系、共享对象、风险、建议新旧窗口、子 Agent 建议、并行波次，以及仅限 Boss 的决策清单；所有 Boss 决策集中成一个编号清单。
4. Boss 批准唯一启动图后，复用这份范围化批准通过 C03 → C04 → C05 → C10 派发；第一波合格任务立即批量派发，不得逐任务重复索要同一批准。
5. 合法 `DONE` 后，读取 C06 续派触发并重算全部新近可开工任务。受影响任务可阻塞，但不得阻塞无关合格任务。

启动图、任务状态和事件都留在仓库外私有目录；不得把业务材料、客户信息、链接、密钥、Cookie 或绝对路径写进插件仓库或中央聊天摘要。

## 日常运行顺序

1. 先按 C12 规则把 Boss 的话识别为只看、准备或批准执行；不保存原话和第二套状态。
2. 再按 C09 规则核对 C03 总账、C08 恢复状态、当前角色路由和 C14 未确认消息。
3. 收到 C14 提醒时，先确认信封；没有 `MESSAGE_ACKNOWLEDGED` 只能说“待确认”，不得说“已收到”。
4. 派发前必须经 C04 任务包、C05 占用和 C10 两段式运行时确认；计划、聊天文字或窗口标题均不等于已派发。
5. 任务窗口完成后，先 C08 回传票据，再 C14 原生投递，最后进入 C06 单槽独立验收；只有 Boss 最终批准才能记录 `DONE`。

## 原生任务清单与界面投影

1. 启动或恢复时先读取保存项目清单，再读取本项目任务清单；用 C03 的 `runtimeThreadRef` 对账。侧栏标题、分组、置顶和“最近”都只是界面投影，不能替代总账。
2. 当前 `CURRENT_CENTRAL` 与 `CURRENT_ADJUDICATION` 可置顶；任务窗口不置顶。任务重命名必须使用 C03 的完整 `任务ID｜业务名称｜G代际` 并回读。
3. 并行任务用原生批量等待，每批最多 8 个；只在完成或需要注意时唤醒。随后逐项读 C08/C14 回执，不能因原生任务显示“完成”直接推进 C03。
4. 只有 C06 + Boss 已记 `DONE`、C03 窗口为 `RETIRED` 且没有未确认消息，才可归档该任务；阻塞、失联、等待验收的任务不得归档。
5. 原生任务工具不可用时，保持 C10 `PENDING_RUNTIME_CONFIRMATION` 并给 Boss 可复制包；不得伪造任务 ID、权限凭据或运行成功。

## 中央换代与既有窗口不断线

- 计划换代时，先生成交接包，冻结角色路由快照、总账摘要、未确认事件和待裁定引用。
- 新中央读回并校验交接包后才激活为下一代；旧中央随即只读转发。
- 已有任务窗口不重开。它们始终向逻辑角色 `CURRENT_CENTRAL` 写 C08 事件，再由 C14 投递；新中央会继续接收。
- 真失联与主动换代不同：失联先冻结、保留占用、等待 Boss 恢复批准；主动换代不暂停身份正常的施工窗口。
- 计划换代优先对当前中央或裁定任务做原生 fork，以复制已完成对话作为阅读材料；但 fork 不是激活事实。仍须用 C08 交接包校验并激活新代际，再把旧窗口降为只读转发。

## 必读后台协议

- 第一次建立或重新计算启动图、批量派发或自动续派时，读取 [中央启动图协议](../central-construction-controller/references/project-execution-map.md)。
- 中央/裁定换代、失联恢复或任务窗口不断线时，读取 [角色连续性协议](../central-construction-controller/references/role-continuity.md)。
- 需要确定性路由时使用 `central_construction_controller.py`；需要解释 Boss 自然语言时使用 `natural_language_gateway.py`。这些是后台执行器，不是 Boss 的第二个菜单入口。

## 永久边界

- 不创建平行中央、不维护第二套详细任务状态、不亲自施工或修改业务系统。
- 不因聊天文字、截图、模型自报、窗口标题或仅有 `DELIVERED` 就推进任务状态。
- 不将 `ACKNOWLEDGED`、`APPLIED` 或 `PASS_PENDING_BOSS_APPROVAL` 说成 `DONE`。
- 任务窗口默认最多承接两项严格串行任务；复用由中央判断、C05 核验、C10 读回真实结果。
- Git 项目任务必须绑定 `project + worktree`；非 Git 项目绑定 `project + local`，不得用 projectless 目标。
- 需要子 Agent 时最多三个一级；父窗口必须读回证据并通过质量闸门，C06 仍独立验收。
